# 리빌딩 계획

2024년 캡스톤 버전(`v1.0-capstone` 태그 / `legacy-2024` 브랜치)을 기준점으로 두고
`main`에서 전면 재구축한다.

## 왜 다시 만드는가

v1의 논지는 "법률 문서는 민감하므로 로컬 LLM을 사용한다"였으나, 실제 구현은
컴퓨팅 자원 부족으로 사용자 질의를 ngrok 공개 터널을 통해 Colab으로 전송했다.
**보안을 위한 설계라는 주장을 구현이 달성하지 못한 상태**였다.

리빌딩의 목표는 이 간극을 메우는 것이다. 자체 통제 서버에서 동작하는
self-hosted 경로를 실제로 구현하고, 프라이버시를 지키기 위해 치러야 하는 비용
(지연 시간·품질)을 실측해 제시한다.

## 목표

1. 데이터가 외부로 나가지 않는 self-hosted 경로를 실제로 구현한다.
2. 동시에 API 백엔드를 지원해 데모에서는 즉각적인 응답을 제공한다.
3. 두 경로의 지연·품질을 실측 비교해 트레이드오프를 데이터로 보인다.
4. 법률 도메인에 필요한 **근거 인용**을 제공한다.
5. 링크 하나로 바로 써볼 수 있는 상태로 상시 운영한다.

## 아키텍처

```
Oracle Cloud A1 (ARM 4 OCPU / 24GB, Always Free) — 전부 자체 호스팅
│
├─ Caddy          리버스 프록시, Let's Encrypt 자동 TLS
├─ Next.js        프론트엔드 (스트리밍 채팅 UI)
├─ FastAPI        백엔드 (SSE 스트리밍)
│   └─ LangGraph  Agentic RAG 그래프
│       ├─ 임베딩  BAAI/bge-m3 (CPU)
│       └─ 검색    Chroma(벡터) + BM25(키워드) 하이브리드
└─ Ollama         self-hosted LLM (프라이버시 모드, 선택 기동)

LLM 백엔드는 설정으로 전환한다.
  api          → Claude          (데모 기본값, 빠름)
  self-hosted  → Ollama 8B       (프라이버시 모드, 느림)

개발·벤치마크: RTX 4060 노트북 (로컬 GPU 구간 측정용)
```

### 메모리 추산

| 구성 | 사용량 |
|---|---|
| 임베딩 모델 (bge-m3) | 약 3GB |
| Next.js (프로덕션) | 약 0.5GB |
| Ollama 8B Q4 (적재 시) | 약 6GB |
| 합계 | 약 10GB / 24GB |

## Agentic RAG 그래프

v1은 `검색 → 생성` 단발 체인이었다. LangGraph로 다음 흐름을 구성한다.

```
질의
 └→ 질의 재작성      법률 용어 정규화, 검색어 확장
 └→ 하이브리드 검색   BM25(조문 번호·용어 정확 매칭) + 벡터(의미 유사)
 └→ 리랭킹
 └→ 관련성 평가 ──── 부족 ──→ 질의 재작성으로 복귀 (최대 N회)
 └→ 답변 생성        근거 조문 인용 포함
 └→ 환각 검증 ────── 실패 ──→ 재생성
 └→ 응답 (출처 표시)
```

법률 도메인에서 하이브리드 검색이 특히 중요한 이유: "근로기준법 제56조"처럼
정확히 일치해야 하는 토큰이 많아 벡터 검색만으로는 놓치기 쉽다.

## 단계별 진행

각 단계를 마칠 때마다 커밋하고 결과를 공유한다.

### 1단계 — 골격
- 프로젝트 구조 재편, 의존성 관리(uv 또는 poetry)
- 설정 체계(pydantic-settings), LLM 백엔드 추상화 인터페이스
- Docker Compose 구성
- **완료 기준:** 백엔드를 설정으로 전환하며 단순 질의응답이 동작

### 2단계 — RAG 코어
- 문서 처리 파이프라인 재작성(청킹 전략 개선)
- 하이브리드 검색 + 리랭킹
- 근거 인용 추적
- **완료 기준:** 인용이 달린 답변이 나오고, 검색 품질이 v1보다 개선됨을 측정으로 확인

### 3단계 — 에이전트
- LangGraph 그래프 구성(재작성·평가·재검색 루프)
- 환각 검증
- **완료 기준:** 검색 실패 케이스에서 자동 재시도가 동작

### 4단계 — 평가 체계
- 한국어 법률 QA 평가셋 구축
- 검색 recall, 근거 충실도(groundedness) 측정
- 백엔드 3종 벤치마크 (Oracle CPU / RTX 4060 / Claude API)
- **완료 기준:** README에 실을 비교표 확보

### 5단계 — 프론트엔드
- Next.js 채팅 UI, SSE 스트리밍 연동
- 인용 출처 표시, 백엔드 전환 UI
- **완료 기준:** 브라우저에서 스트리밍 응답과 출처가 보임

### 6단계 — 배포
- Oracle A1 프로비저닝, Caddy + TLS
- GitHub Actions CI(테스트·린트) 및 배포 파이프라인
- 유휴 인스턴스 회수 방지용 헬스체크
- **완료 기준:** 공개 URL로 상시 접속 가능

## LLM 호출 전략

2026-09-23 Gemini 무료 티어 실측을 근거로 결정했다.

**실측 결과** — `gemini-3.6-flash` 반복 호출 시 1회차 503(2.99초), 2회차 200
정상 응답(8.80초). 503은 간헐적이며 모델 자체의 문제가 아니다. 실패는 3초 만에
즉시 거절되고, 정상 응답은 8초 이상 걸린다.

| 용도 | 방식 | 근거 |
|---|---|---|
| 대화형 질의응답 | 동기 호출 + 스트리밍 + 지수 백오프 재시도 | 사용자가 대기하는 경로. 503이 간헐적이므로 폴백보다 재시도가 적합 |
| 04단계 벤치마크 | Batch API | 실시간성 불필요. 분당 5회 제한과 503을 회피하고 비용도 절반 |

**스트리밍을 앞당긴다.** 응답이 8초를 넘으므로 스트리밍 없이는 체감 품질을
평가할 수 없다. 원래 05단계였으나 03단계 착수 전에 백엔드 SSE를 먼저 구현한다.

**API 호출은 사용자 허락을 받고 수행한다.** 무료 티어는 분당 5회 등 한도가
작으므로 반복 테스트를 임의로 돌리지 않는다.

## 유의사항

**Oracle Always Free 유휴 회수** — CPU 사용률이 7일간 10% 미만으로 지속되면
인스턴스가 회수될 수 있다. 주기적 헬스체크를 배치해 방지한다.

**CPU 추론 속도** — ARM 4 OCPU에서 8B Q4는 약 4~8 tok/s로, 300토큰 답변에
40~75초가 걸린다. 데모 기본값을 API로 두고, self-hosted는 프라이버시 모드로
명시해 선택하게 한다. 스트리밍으로 체감을 완화한다.

**법률 자문 아님** — 생성된 답변은 참고용이며 법률 자문이 아니라는 고지를
UI에 표시한다.
