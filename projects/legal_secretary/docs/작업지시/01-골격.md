# 작업 지시 01 — 골격

## 목표

리빌딩의 기반 구조를 만든다. 설정으로 LLM 백엔드를 전환할 수 있고, API 키 없이도
전체가 실행·테스트되는 상태까지 도달한다.

검색(RAG)은 이 단계의 범위가 아니다. `/api/ask`는 검색 없이 LLM에 질의를 그대로
전달하는 수준이면 된다. 검색은 02단계에서 얹는다.

## 사전 조건

- 작업 디렉토리: `/home/user/Desktop/ML` (git 저장소, 브랜치 `main`)
- [설계.md](../설계.md)를 먼저 읽을 것. 디렉토리 구조·설정 키·백엔드 팩토리
  방침이 모두 거기 정의되어 있다.
- Python 3.12.7 / aarch64 / 인터넷 연결 가능
- **Docker는 이 단계에서 다루지 않는다** (6단계로 이연)

## 할 일

### 1. uv 설치 및 프로젝트 초기화
- uv를 설치한다 (aarch64 바이너리).
- `backend/pyproject.toml`을 만든다. 의존성:
  `fastapi`, `uvicorn[standard]`, `pydantic-settings`, `langchain-core`,
  `langchain-anthropic`, `langchain-ollama`, `langchain-community`
  개발 의존성: `pytest`, `httpx`, `ruff`

### 2. 디렉토리 재편
- 설계.md의 구조대로 `backend/app/...`, `data/`를 만든다.
- `pdf_data/*.pdf` → `data/pdf/` 로 이동한다 (`git mv` 사용).
- `rag_temp/template.txt` → `backend/app/prompts/legal_qa.txt` 로 이동한다.
- 아래 레거시 자산을 **삭제**한다. `legacy-2024` 브랜치와 `v1.0-capstone`
  태그에 보존되어 있으므로 유실 위험이 없다.
  - `app.py`, `app.ini`, `templates/`, `static/`, 빈 `pdf_data/`, `rag_temp/`
- `archive/`와 `docs/`는 **건드리지 않는다**.
- `.gitignore`를 갱신한다: `data/vector_store/`, `.env`, `__pycache__`, `.venv`

### 3. 설정 (`backend/app/config.py`)
- `pydantic-settings`의 `BaseSettings`로 설계.md의 설정 표를 그대로 구현한다.
- `.env` 파일을 읽도록 한다.
- `LLM_BACKEND` 기본값은 `fake`.
- 저장소 루트에 `.env.example`을 만든다 (실제 키는 절대 넣지 말 것).

### 4. LLM 백엔드 (`backend/app/llm/`)
- `factory.py` — 설정을 받아 `BaseChatModel`을 반환하는 함수. 설계.md 참고.
  별도 추상 클래스를 만들지 말 것.
- `fake.py` — 키 없이 테스트 가능한 결정론적 백엔드. LangChain의
  `FakeListChatModel` 등을 활용해도 되고 동등하게 직접 구현해도 된다.
  같은 입력에 항상 같은 출력을 내야 한다.

### 5. API (`backend/app/`)
- `main.py` — FastAPI 앱 생성, 라우터 등록.
- `api/schemas.py` — 설계.md의 응답 스키마. 이 단계에서 `citations`는 빈 배열로
  둔다 (02단계에서 채움).
- `api/routes.py`
  - `GET /health` → 상태와 현재 활성 백엔드 이름 반환
  - `POST /api/ask` → 질의를 LLM에 전달하고 답변 반환
- 서비스 로직은 라우트 함수 안에 직접 쓰지 말고 분리한다. 5단계에서 스트리밍을
  얹을 때 재작성하지 않도록, 비동기로 작성할 것.

### 6. 테스트 (`backend/tests/`)
- 설정에서 백엔드 전환이 동작하는지
- `GET /health` 응답
- `POST /api/ask` 응답이 스키마를 만족하는지
- 전부 `fake` 백엔드로, 네트워크·키 없이 통과해야 한다.

### 7. 작업 로그
- `docs/작업일지.md`를 만들고 이번 단계 항목을 기록한다.
  포함할 것: 날짜, 한 일, 내린 결정과 그 이유, 막혔던 지점과 해결 방법,
  다음 단계에 넘기는 주의사항.
- 이 파일은 이후 단계에서 계속 덧붙여 쓸 것이므로, 단계별 섹션 구조로 만든다.

## 완료 판정 기준

아래가 **전부** 충족되어야 완료다. 각 항목을 실제로 실행해 확인할 것.

1. `cd backend && uv run pytest` — 전부 통과
2. `cd backend && uv run uvicorn app.main:app --port 8000` — 정상 기동
3. `curl localhost:8000/health` — 200, 활성 백엔드가 `fake`로 표시
4. `curl -X POST localhost:8000/api/ask -H 'Content-Type: application/json' -d '{"question":"테스트"}'`
   — 200, 설계.md의 응답 스키마와 일치
5. `LLM_BACKEND=self_hosted` 로 환경변수를 바꾸면 `/health`의 백엔드 표시가
   바뀐다 (Ollama 서버가 없으므로 실제 질의는 실패해도 무방. 전환 자체를 확인)
6. `uv run ruff check .` — 통과
7. API 키 없이 1~6이 모두 동작

## 금지 사항

- **커밋하지 말 것.** 검토 후 상위 에이전트가 커밋한다.
- `docs/` 안의 기존 문서(`리빌딩계획.md`, `설계.md`, `구현노트.md`)를 수정하지
  말 것. `작업일지.md` 생성만 허용.
- `archive/` 를 건드리지 말 것.
- `.env` 파일에 실제 키를 넣지 말 것.
- 3단계 이후 내용(LangGraph, 검색, 리랭킹, 프론트엔드)을 미리 만들지 말 것.
