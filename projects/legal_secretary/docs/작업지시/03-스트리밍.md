# 작업 지시 03 — 스트리밍 (SSE)

## 배경

무료 티어 Gemini의 응답 지연이 실측 23~175초로 크게 요동친다. 원인은 서버 측
혼잡이며 클라이언트에서 줄일 수 없다는 것이 측정으로 확인됐다(작업일지 참고).
따라서 **지연을 없애는 대신 사용자가 기다릴 수 있게 만드는 것**이 이 단계의
목표다.

self-hosted(Ollama, ARM CPU) 모드는 40~75초가 예상되므로, 스트리밍은 그쪽에도
필수다.

## 목표

`/api/ask/stream` 엔드포인트를 추가해 답변을 토큰 단위로 전송한다.

**핵심 설계**: 인용은 검색 직후(약 1.4초)에 이미 확정되므로 **LLM 생성을
기다리지 않고 먼저 보낸다.** 생성이 60초 걸려도 사용자는 2초 안에 근거 조문을
본다. 이것이 이 단계에서 가장 중요한 부분이다.

## 사전 조건

- 작업 디렉토리 `/home/user/Desktop/ML`, 브랜치 `main`
- `uv`는 `~/.local/bin/uv`. 명령은 `backend/`에서 `uv run ...`
- `langchain-core`는 **1.x 계열**이다. v0.3 예제를 베끼지 말 것
- [설계.md](../설계.md), [작업일지.md](../작업일지.md) 선행 숙지

## 할 일

### 1. 기존 `/api/ask` 유지

비스트리밍 엔드포인트를 **삭제하지 말 것.** 04단계 벤치마크에서 응답 시간을
측정하려면 비스트리밍이 단순하고, 배치 처리에도 필요하다. 두 엔드포인트가
같은 검색 로직을 공유하도록 한다.

### 2. SSE 엔드포인트 `POST /api/ask/stream`

이벤트 종류와 전송 순서:

| 순서 | event | data | 시점 |
|---|---|---|---|
| 1 | `citations` | 인용 배열 (기존 스키마와 동일) | 검색 직후 |
| 2 | `status` | `{"state": "generating"}` | LLM 호출 시작 |
| 3 | `token` | `{"text": "..."}` (반복) | 토큰 도착마다 |
| 4 | `done` | `{"backend": "...", "elapsed": 12.3}` | 완료 |
| — | `error` | `{"message": "...", "retryable": true}` | 실패 시 |

표준 SSE 형식을 따른다.

```
event: citations
data: {"citations": [...]}

event: token
data: {"text": "근로"}

```

### 3. 토큰 추출 시 주의 — 이미 겪은 버그

LangChain v1의 Gemini는 `content`를 **구조화된 블록 리스트**로 반환한다.
비스트리밍에서 `str(content)`를 쓰다가 리스트 repr과 내부 서명 필드가 그대로
노출된 적이 있다(커밋 c6abc20). **스트리밍 청크에도 동일한 문제가 있으므로**
`chunk.text` 프로퍼티로 추출할 것. 청크마다 빈 문자열이 올 수 있으니 걸러낸다.

### 4. 장시간 대기 대응

응답이 60초 이상 걸릴 수 있다. 연결이 살아있음을 알리기 위해 **생성 중 토큰이
오지 않는 동안 주기적으로**(예: 10초 간격) `status` 이벤트를 보낸다.

```
event: status
data: {"state": "waiting", "elapsed": 30.1}
```

타임아웃은 설정값으로 둔다(`STREAM_TIMEOUT_SECONDS`, 기본 180).
초과 시 `error` 이벤트를 보내고 스트림을 정상 종료한다. 예외를 그대로
던져 연결이 끊기게 하지 말 것.

### 5. fake 백엔드의 스트리밍 지원

테스트를 키 없이 돌려야 하므로 `fake` 백엔드도 `astream`을 지원해야 한다.
결정론적으로 여러 청크를 나누어 반환하게 한다.

### 6. 설정 추가

| 키 | 기본값 | 설명 |
|---|---|---|
| `STREAM_TIMEOUT_SECONDS` | `180` | 스트림 전체 타임아웃 |
| `STREAM_HEARTBEAT_SECONDS` | `10` | 토큰이 없을 때 status 전송 주기 |

`.env.example`에도 반영할 것.

### 7. 테스트

전부 `fake` 백엔드로, 외부 API 호출 없이 통과해야 한다.

- `citations` 이벤트가 **첫 번째로** 전송되는지 (이 단계의 핵심)
- `token` 이벤트들을 이어붙이면 비스트리밍 `/api/ask`의 answer와 같은지
- `done` 이벤트가 마지막에 오는지
- 벡터스토어가 비었을 때 `error` 이벤트로 처리되는지 (예외 전파 금지)
- 기존 테스트 20건이 계속 통과하는지

### 8. 수동 확인

`curl -N`으로 실제 스트리밍을 확인하고 결과를 보고에 포함할 것.

```bash
curl -N -X POST localhost:8000/api/ask/stream \
  -H 'Content-Type: application/json' \
  -d '{"question":"연장근로 수당은 어떻게 계산하나요?"}'
```

**`fake` 백엔드로 확인할 것. 외부 API를 호출하지 말 것.**

### 9. 작업일지

## 완료 판정 기준

실제로 실행해 확인할 것.

1. `uv run pytest` — 전부 통과 (기존 20건 + 신규)
2. `uv run ruff check .` — 통과
3. `curl -N`으로 `/api/ask/stream` 호출 시 `citations`가 가장 먼저 도착
4. `token` 이벤트가 여러 번에 나뉘어 도착 (한 번에 다 오지 않음)
5. 이어붙인 토큰이 `/api/ask`의 answer와 일치
6. 벡터스토어가 빈 상태에서 `error` 이벤트로 정상 처리 (연결 끊김 없음)
7. 위 전부 API 키 없이 동작

## 금지 사항

- **커밋하지 말 것.** 검토 후 상위에서 커밋한다.
- **외부 LLM API를 호출하지 말 것.** 반드시 `LLM_BACKEND=fake`로 테스트.
  저장소 루트 `.env`에 실제 키가 있으나 사용·출력·커밋 금지.
- 기존 `/api/ask`를 제거하거나 동작을 바꾸지 말 것
- LangGraph·에이전트 루프를 만들지 말 것 (다음 단계)
- 프론트엔드를 만들지 말 것 (05단계)
- `docs/` 기존 문서 수정 금지 (`작업일지.md` 추가만 허용)
- 프롬프트 템플릿(`legal_qa.txt`)을 수정하지 말 것 — 사용자가 현행 유지를 지시함
