# 개발일지

## 2026-08-28 ~ 2026-08-31 — 기획서 작성과 노트북 단계별 구현

명세서를 받고 바로 코드부터 짜지 않고, 먼저 데이터 구조·반환 형식·오류 코드를
`기획서.md`로 확정했다. Sonnet에게 구현을 넘길 걸 고려해서, 함수 시그니처와 동작
순서까지 문서에 못박아뒀다 — 설계가 비어 있으면 구현자가 설계까지 대신하게 되고,
그러면 왜 그렇게 만들었는지 설명을 못 하게 된다.

### 결정 — 반환 형식을 `{ok, data/error, message}`로 통일

도구 7개가 제각각 다른 모양으로 반환하면 Agent loop가 성공/실패를 함수마다 다르게
판단해야 한다. 처음부터 하나의 규약으로 못박고 시작했다.

### 결정 — 카테고리를 지출/수입으로 분리, 예산은 지출에만

"월급 예산 300만원" 같은 말이 안 되는 요청을 프롬프트가 아니라 코드 검증
단계(`_validate_category(category, "지출")`)에서 차단하기로 했다.

### 개발 방식 — 노트북에 [설명 셀 → 코드 뼈대 → 정답(접힌 상태)]로 구조화

처음엔 설명을 위에 몰아 쓰고 코드는 큰 덩어리로 둬서, 셀 하나가 화면을 넘어가고
정답을 안 보면 뭘 채워야 할지 감이 안 잡히는 문제가 있었다. 기능 단위(검증 함수 1개,
도구 함수 1개)로 [설명] + [코드 뼈대] 쌍을 나누고, 정답은 `<details>` 접은 상태로
바로 아래 두는 구조로 다시 짰다. 막혔을 때만 펼쳐보게 하기 위해서였다.

### 버그 1 — `_validate_category`에서 수입/지출 목록이 뒤바뀜

```python
elif transaction_type == "수입":
    return category in self.expense_categories   # income_categories여야 하는데 잘못 복붙됨
```

`if`/`elif` 두 블록이 구조가 똑같고 한 단어만 다른 상황이라 복붙하면서 놓쳤다.
`manager._validate_category("월급", "수입")`이 `False`가 나와야 정상인데 반대로
나와서 발견했다.

### 버그 2 — `_validate_month`가 자릿수를 검사한다고 잘못 설명함

`strptime`의 `%m`, `%d`는 자릿수를 강제하지 않는다. `"2026-8"`도 그대로 통과된다.
처음엔 노트북에 "두 자리가 아니면 False"라고 잘못 적어뒀는데, 실행해서 `"2026-8"`이
`True`로 나오는 걸 보고서야 틀린 설명이라는 걸 알았다. 실제로 막히는 건 13월처럼
없는 값이거나 뒤에 날짜까지 붙어 형식 자체가 안 맞는 경우뿐이다. 노트북 설명과
`set_budget` 오류 테스트 예시를 전부 `"2026-13"` 기준으로 고쳤다.

### 검토했다가 버린 아이디어 — import를 함수로 감싸서 파일 간에 재사용

"각 파일마다 import를 반복해서 쓰는 게 비효율적이지 않나"는 질문에서 출발해서,
`imports.py`에 `def a_imports(): import os, ...; return os, ...` 형태로 만들고
`os, load_dotenv = a_imports()`처럼 받아 쓰는 방식을 검토했다. 기술적으로는
동작하지만, 반환 순서와 언패킹 순서를 두 파일에서 계속 맞춰야 하고(개수가 같으면
순서가 바뀌어도 에러 없이 조용히 엉뚱한 값이 들어감), IDE 자동완성·정적 분석 도구가
이 패턴을 추적하지 못한다. 얻는 이득이 거의 없어서 표준적인 파일별 명시적 import로
유지하기로 했다.

### 중간 제출본을 별도 폴더로 분리

학습용 노트북(`main.ipynb`)은 계속 진행 중인 상태로 두고, 제출 시점(3-2까지 완료)의
스냅샷만 `budget_manager.py` + `main.py`로 정리해 별도 폴더(`260831_김민석_중간제출`)에
남겼다. 노트북은 진행형 학습 기록이고, 제출본은 그 시점의 결과물이라 성격이 달라서
같은 파일을 재사용하지 않고 분리했다.

## 2026-09-03 — 방치된 프로젝트를 실제로 완성 상태까지 확인

포트폴리오 정리 중 GitHub 저장소 목록과 로컬 폴더를 비교하다가, 이 프로젝트가
**로컬 폴더 자체가 없는 상태**로 발견됐다. 원래 위치는
`C:\Users\HOME\Desktop\260811\mini0829_개인예산관리agent`였고, `git/` 폴더 아래로
옮기고 저장소명(`personal-budget-ai-agent`)에 맞춰 폴더명도 통일했다.

### 발견 1 — README와 실제 코드 상태가 전혀 달랐다

README는 "Phase 2/10 진행 중"이라고 적혀 있었지만, GitHub에는 최초 커밋(`init`) 하나만
올라가 있고 **로컬에는 그 뒤로 1,300줄 넘게 추가된 미커밋 코드**가 있었다. 실제로 열어보니
`budget_manager.py`에 필요한 메서드(등록·검색·수정·삭제·예산 설정/조회·월별 보고서)가
전부 구현돼 있었고, `agent.py`에도 도구 7개 등록과 Agent loop가 완성돼 있었다.
즉 "미완성"이 아니라 "완성된 코드가 커밋·push되지 않아 GitHub에는 안 보였던 것"이었다.

### 발견 2 — 폴더 이동으로 `.env` 경로가 깨짐

`main.ipynb`의 일부 셀이 `load_dotenv("../.env")`로 **상위 폴더의 공용 `.env`**를
가리키고 있었다. 원래 위치(`260811/`)에서는 그게 `260811/.env`(TMDB, LangSmith 등
여러 프로젝트가 같이 쓰는 공용 파일)를 가리켰는데, 폴더를 옮기면서 그 경로가 깨졌다.
이 프로젝트 전용 `.env`를 새로 만들어 `GEMINI_API_KEY`만 옮겨 담아 해결했다 —
다른 프로젝트의 키와 섞인 공용 파일에 계속 의존하지 않도록.

### 발견 3 — 진짜 버그: Windows 콘솔 인코딩

`python agent.py`를 실제로 실행해보니 두 가지가 났다.

1. 첫 실행: Gemini가 `400 Invalid JSON payload: syntax error in request body`로 거부.
   `input()`으로 받은 한글이 Windows 기본 콘솔 인코딩(cp949)으로 깨져서, 그 문자열을
   JSON으로 감싸 보낼 때 유효하지 않은 바이트가 섞여 들어간 것이었다.
2. 두 번째 실행: 이번엔 요청은 정상 처리됐지만, 결과를 출력하는 `print()`가 이모지
   (`🔧`, `❌`)를 cp949로 인코딩하지 못해 `UnicodeEncodeError`로 프로그램이 죽었다.
   `run_agent()`의 `try/except`가 API 오류는 잡아주지만, **그 예외를 출력하는
   순간 또 다른 인코딩 예외가 나는** 구조라 안전장치가 무력화됐다.

`httpx.Client.send`를 몽키패치해서 실제로 나가는 JSON 요청 본문을 직접 찍어보고,
`PYTHONIOENCODING=utf-8`로 강제했을 때는 문제없이 끝까지 동작하는 것을 확인해
원인을 좁혔다. 콘솔 인코딩 문제라는 게 확정되자, 매번 환경변수를 손으로 설정하게
하는 대신 코드 자체에서 해결하는 쪽을 택했다.

```python
if sys.platform == "win32":
    sys.stdin.reconfigure(encoding="utf-8")
    sys.stdout.reconfigure(encoding="utf-8")
```

`agent.py` 맨 위에 이 네 줄을 추가한 뒤 다시 실행하니, 별도 설정 없이
"오늘 점심으로 12000원 썼어" → 등록 → "이번 달 식비 얼마나 썼어?" → 예산 미설정
안내 + 검색 결과 요약까지 전부 정상 출력됐다.

### 배운 것

**로컬에서 되는 것과 다른 환경(여기서는 Windows 콘솔 코드페이지)에서 되는 것은 다르다.**
mealmate 개발일지의 "내 컴퓨터에서 되는 것과 배포에서 되는 것은 다르다"와 같은 종류의
교훈을 콘솔 환경 차이로 다시 겪었다. 코드 자체(Agent 로직, 도구 설계)는 처음부터
문제가 없었고, 실행 환경의 기본값 하나가 전체를 막고 있었을 뿐이다.

또한 "로컬에 코드가 있다"와 "GitHub에 반영돼 있다"는 다른 이야기라는 것도 다시 확인했다
(포트폴리오 저장소의 Supabase keep-alive 사고 때와 같은 결).
