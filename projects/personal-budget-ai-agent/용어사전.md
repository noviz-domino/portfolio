# 용어사전

> 코드에 나오는 영어 이름(변수·함수·키워드)의 뜻과, 이 프로젝트에서 왜 그 이름을 썼는지 정리한 문서.
> 진행하면서 계속 추가된다. (마지막 갱신: Phase 2 진행 중)

---

## 1. 프로젝트에서 만든 것들 (우리가 지은 이름)

### 클래스

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `BudgetManager` | budget(예산) + manager(관리자) | "예산을 관리하는 사람/것" — 거래·예산 데이터를 전부 들고 관리하는 클래스라서 |

### 클래스 속성 (`self.___`)

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `data_file` | data(자료) + file(파일) | 데이터를 저장할 "파일"의 이름을 담는 곳 |
| `transactions` | transaction(거래) + s(복수) | 거래 "여러 개"를 담은 리스트라서 복수형 |
| `next_id` | next(다음) + id(식별번호) | 다음에 부여할 거래 번호 |
| `expense_categories` | expense(지출) + categories(분류들) | 지출 카테고리 목록 |
| `income_categories` | income(수입) + categories(분류들) | 수입 카테고리 목록 |
| `budgets` | budget(예산) + s(복수) | 월·카테고리별 예산들을 담은 딕셔너리 |

### 도구 함수 (메서드)

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `add_transaction` | add(추가하다) + transaction(거래) | 거래를 추가한다 |
| `search_transactions` | search(검색하다) + transactions(거래들) | 거래들을 검색한다 |
| `update_transaction` | update(갱신하다, 수정하다) + transaction(거래) | 거래 하나를 수정한다 |
| `delete_transaction` | delete(삭제하다) + transaction(거래) | 거래 하나를 삭제한다 |
| `set_budget` | set(설정하다) + budget(예산) | 예산을 설정한다 |
| `get_budget_status` | get(가져오다, 조회하다) + budget(예산) + status(현황) | 예산 현황을 조회한다 |
| `generate_monthly_report` | generate(생성하다) + monthly(월간의) + report(보고서) | 월간 보고서를 생성한다 |

> `get`과 `set`은 프로그래밍에서 아주 흔한 짝이다. `set_X` = "X를 정한다", `get_X` = "X를 가져온다/알아낸다".

### 검증 헬�― (내부용 함수, `_`로 시작)

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `_validate_amount` | validate(검증하다) + amount(금액) | 금액이 올바른지 검사(+ 정수로 변환) |
| `_validate_date` | validate(검증하다) + date(날짜) | 날짜 형식이 올바른지 검사 |
| `_validate_month` | validate(검증하다) + month(월) | 월 형식이 올바른지 검사 |
| `_validate_category` | validate(검증하다) + category(분류) | 카테고리가 허용 목록에 있는지 검사 |
| `_save` | save(저장하다) | 데이터를 파일에 저장 |
| `_load` | load(불러오다, 싣다) | 파일에서 데이터를 불러옴 |

> 이름 앞의 `_`(밑줄)은 "이건 클래스 내부에서만 쓰는 보조 도구다, 외부(Gemini)에는 노출 안 한다"는 파이썬 관례 표시.

### 매개변수 이름

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `transaction_type` | transaction(거래) + type(종류) | 거래의 종류(수입/지출). `type`만 쓰면 파이썬 내장 함수 이름과 겹쳐서 위험 |
| `category` | 분류, 범주 | 식비/교통비 같은 분류 |
| `amount` | 금액, 양 | 거래 금액 |
| `date` | 날짜 | "YYYY-MM-DD" |
| `description` | 설명, 묘사 | 거래에 대한 메모 |
| `start_date` | start(시작) + date(날짜) | 검색 기간의 시작일 |
| `end_date` | end(끝) + date(날짜) | 검색 기간의 종료일 |
| `keyword` | key(핵심) + word(단어) | 설명 안에서 찾을 핵심 단어 |
| `transaction_id` | transaction(거래) + id(식별번호) | 수정·삭제할 대상 거래의 번호 |
| `month` | 월, 달 | "YYYY-MM" |

### 함수 안에서 쓰는 지역 변수

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `value` | 값 | 검증을 통과해서 확정된 값을 담는 흔한 이름 |
| `results` | result(결과) + s(복수) | 검색 조건을 통과한 결과들을 모으는 리스트 |
| `t` | transaction(거래)의 줄임 | `for t in self.transactions:` 처럼 반복문에서 "거래 하나"를 가리킬 때. 매번 `transaction`이라 쓰기 번거로워 관용적으로 한 글자로 줄임 |
| `target` | 목표, 대상 | `update_transaction`/`delete_transaction`에서 "지금 찾고 있는 그 거래" |
| `before` | ~전에 | 수정하기 **전** 상태를 복사해둔 것 |
| `after` | ~후에 | 수정한 **후** 상태 |
| `removed` | remove(제거하다)의 과거분사 | 삭제된 거래 내용을 담아두는 변수 |
| `message` | 메시지, 전달 문구 | 사용자에게 보여줄 안내 문장 |
| `changes` | change(변화)의 복수 | "무엇이 어떻게 바뀌었는지" 문장들을 모은 리스트 |

### 반환 딕셔너리의 키

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `ok` | 괜찮다, 성공했다 (구어체) | 성공/실패를 가장 짧고 명확하게 표현하는 관용적인 이름 |
| `data` | 자료, 데이터 | 실제 결과물을 담는 자리 |
| `error` | 오류 | 실패했을 때의 오류 코드 |
| `message` | 메시지 | 사람이 읽을 문장 |
| `count` | 개수, 세다 | 몇 건인지 |
| `transactions` | 거래들 | 결과로 나온 거래 목록 |

### 오류 코드 (전부 `INVALID_` + 무엇이 잘못됐는지)

| 이름 | 뜻 |
|---|---|
| `INVALID_TYPE` | invalid(유효하지 않은) + type(유형) → 거래 유형이 잘못됨 |
| `INVALID_AMOUNT` | 금액이 잘못됨 |
| `INVALID_DATE` | 날짜가 잘못됨 |
| `INVALID_MONTH` | 월이 잘못됨 |
| `INVALID_CATEGORY` | 카테고리가 잘못됨 |
| `NOT_FOUND` | not(아니다) + found(찾다의 과거분사) → 찾을 수 없음 |
| `NOTHING_TO_UPDATE` | nothing(아무것도 없음) + to update(수정할) → 수정할 게 없음 |
| `NO_BUDGET_SET` | no(없음) + budget(예산) + set(설정된) → 설정된 예산이 없음 |
| `NO_DATA` | 데이터가 없음 |

## 2. 파이썬 문법 용어

| 용어 | 뜻 | 이 프로젝트에서 쓰인 곳 |
|---|---|---|
| `self` | 자기 자신 | 클래스 메서드에서 "지금 이 인스턴스"를 가리키는 이름 |
| `try` / `except` | 시도하다 / ~을 제외하고 | 에러가 나도 프로그램이 죽지 않게 감싸는 문법 |
| `ValueError` | value(값) + Error(오류) | 타입은 맞는데 값이 이상할 때 나는 에러 (예: `int("사과")`) |
| `TypeError` | type(타입) + Error(오류) | 타입 자체가 안 맞을 때 나는 에러 (예: `int(None)`) |
| `continue` | 계속하다 | 반복문에서 이번 회차를 건너뛰고 다음으로 넘어감 |
| `break` | 부수다, 끊다 | 반복문 자체를 완전히 끝냄 |
| `for ... in ...` | ~안에 있는 것들에 대해 | 리스트 등을 하나씩 순회하는 반복문 |
| `lambda` | (그리스 문자 λ, 수학의 람다 계산에서 따옴) | 이름 없이 즉석에서 만드는 짧은 함수 |
| `key` | 열쇠 | (1) 딕셔너리의 "키" (2) `sort()`가 "무엇을 기준으로 비교할지" 받는 매개변수 |
| `sort` | 정렬하다 | 리스트 순서를 바꾸는(원본을 직접 수정하는) 메서드 |
| `sorted` | sort의 과거분사 | 원본은 안 건드리고 정렬된 새 리스트를 만드는 함수 |
| `append` | 덧붙이다 | 리스트 맨 끝에 항목 추가 |
| `copy` | 복사(하다) | 딕셔너리/리스트를 별도로 복제 |
| `is not None` | ~이 아니다 / 아무것도 아님(없음) | "값이 있는지" 확인하는 대표적인 방법 |
| `return` | 돌려주다 | 함수의 결과값을 내보냄 |
| `def` | define(정의하다)의 줄임 | 함수를 정의하는 키워드 |
| `import` | 가져오다, 수입하다 | 다른 모듈의 기능을 가져다 씀 |
| `raise` | 들어올리다, (문제를) 제기하다 | 에러를 일부러 발생시킴 |
| `strptime` | string(문자열) + parse(해석하다) + time(시간) | 문자열을 datetime으로 변환 |
| `strftime` | string(문자열) + format(형식) + time(시간) | datetime을 문자열로 변환 |
| `enumerate`, `len`, `dict`, `list` | 열거하다 / 길이 / 사전 / 목록 | 파이썬 기본 함수·자료형 이름 그대로 |

## 3. Phase 5 이후에 나올 용어 (미리보기)

| 이름 | 영어 뜻 | 왜 이 이름인가 |
|---|---|---|
| `client` | 의뢰인, 고객 | Gemini 서버에 요청하는 "손님" 역할의 객체 |
| `interaction` | 상호작용 | 사용자와 모델 사이의 한 번의 대화 교환 |
| `step` | 단계, 걸음 | 응답 안에서 일어난 한 단계(도구 호출 등) |
| `function_call` | 함수 호출 | 모델이 "이 함수를 불러달라"고 요청하는 단계 |
| `function_result` | 함수 결과 | 우리가 실행한 결과를 모델에 돌려줄 때의 형식 |
| `TOOL_FUNCTIONS` | tool(도구) + functions(함수들) | "이름 → 실제 함수" 변환표 |
| `TOOLS` | 도구들 | Gemini에 등록할 schema 목록 |
| `SYSTEM_INSTRUCTION` | system(시스템) + instruction(지시) | 모델에게 주는 역할/행동 규칙 |
| `execute_tool_call` | execute(실행하다) + tool call(도구 호출) | 도구 호출 요청을 안전하게 실행하는 함수 |
| `run_agent` | run(실행하다) + agent(에이전트) | Agent 전체 루프를 실행하는 함수 |
| `previous_interaction_id` | previous(이전의) + interaction + id | 직전 대화의 식별번호 (대화를 이어가기 위해) |
| `arguments` | 인자, 논거 | 함수를 부를 때 넘기는 값들 |

## 사용법

코드 읽다가 뜻 모르는 이름 나오면:
1. 먼저 이 파일에서 찾아보기
2. 없으면 물어보기 → 답 받으면 이 파일에 추가 요청하기
