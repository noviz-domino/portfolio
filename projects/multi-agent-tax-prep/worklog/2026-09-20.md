## 테스트가 통과했는데 실패한 일

라우터 테스트 5개가 전부 통과했다. 그런데 로그를 읽어보니
**내가 만든 전제조건 검사가 한 번도 실행되지 않았다.**

```
[4] [router] research → review   ← 라우터가 알아서 research를 붙였다
```

기대값은 맞았지만 **다른 이유로 맞은 것**이었다. 안전망이 동작하는지는 여전히 몰랐다.

| | 통과한 이유 |
|---|---|
| 내가 의도한 것 | review가 정보 없음을 감지 → research로 보냄 |
| 실제로 일어난 것 | 라우터가 애초에 research를 넣어줌 |

전제조건 검사는 순수 파이썬이라 LLM 없이 직접 부를 수 있다.
단위 테스트를 따로 만들어 확인했더니, 그제야 이 줄이 찍혔다.

```
[planning] 판단에 필요한 정보가 없습니다 → research를 먼저 실행합니다
```

## 배운 것

**"통과했다"와 "내가 짠 코드가 동작했다"는 다르다.**
다른 경로로 우연히 같은 결과가 나오면 테스트는 초록불인데 그 코드는 한 번도 안 돌아본 상태다.
나중에 거기 버그가 생겨도 테스트는 계속 통과한다.

## 테스트를 두 겹으로 나눴다

| 파일 | 확인하는 것 | LLM 호출 |
|---|---|---|
| `test_router.py` | 라우터가 요청을 잘 분류하나 | 5회 |
| `test_preconditions.py` | 라우터가 놓쳐도 각 노드가 막아내나 | 0회 |

단위 테스트가 공짜라는 게 크다. 리팩터링할 때 부담 없이 돌릴 수 있다.
LLM을 쓰는 프로젝트에선 통합 테스트 한 번이 실제 돈이라 이 구분이 더 중요해진다.
