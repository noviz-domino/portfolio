## 조사 에이전트의 3단 구조

어제 만든 판정 함수를 가운데 끼워 넣었다.

```
① 추출 (LLM)    대화에서 소득 정보를 구조화된 형태로 뽑아낸다
② 판정 (파이썬)  기준선과 비교한다 — 숫자 비교는 코드가 정확하다
③ 서술 (LLM)    판정 결과를 사람이 읽을 문장으로 풀어낸다
```

LLM은 자연어를 다루는 앞뒤 두 단계만 맡는다.
서술 프롬프트에 **"판정 결과는 이미 계산되어 주어진다. 숫자를 새로 계산하지 말고
주어진 결과를 설명만 한다"**를 못 박아, LLM이 제멋대로 계산하지 않게 했다.

## 프롬프트 2층 구조

```python
ROLE   = "너는 사용자 상황을 여러 관점에서 파악하는 조사 담당이다..."   # 도메인 무관
DOMAIN = "참고 지식 — 종합소득세. 업종 그룹은 가군/나군/다군으로..."    # 교체 가능

prompt = ROLE + "\n" + DOMAIN
```

나중에 연말정산 도메인을 얹을 때 `DOMAIN`만 갈아끼우면 된다.
세 에이전트 모두 같은 방식으로 나눴다.

## 검증에서 하나 걸렸다

시나리오 5개를 돌렸더니 4개는 통과했는데 하나가 틀렸다.

```
> 노트북 200만원, 커피값, 코딩 강의 50만원 썼는데 경비 되나?

[router] research   ← 검토를 빼먹었다
[실행 순서] 1. research
```

**상황 파악만 하고 정작 지출 판단을 안 했다.** 사용자가 구체적인 항목을 대고 물었는데
조사로 끝나버린 것이다.

라우터 프롬프트에 규칙을 하나 추가했다.

> 사용자가 구체적인 항목·내용·초안을 제시하면서 판단이나 점검을 요구하면
> review를 반드시 포함한다. 판단을 요구받았는데 파악만 하고 끝내면 요청에 답하지 못한 것이다.

고친 뒤 `research → review`로 정상 동작했다.

## 테스트 하나가 깨졌다

스텁을 실제 구현으로 바꾸니 `test_preconditions.py`가 **"LLM 호출 0회" 약속을 어기게** 됐다.
스텁일 때는 그냥 문자열을 돌려주던 자리에서 이제 실제 호출이 나간다.

LLM에 닿지 않는 경로만 남기고, 대기열 함수(`handoff`, `ask_user`, `request_research`)는
에이전트를 거치지 않고 직접 부르도록 고쳤다.

테스트가 구현에 너무 붙어 있으면 이런 일이 생긴다.
순수 로직만 떼어 테스트하는 쪽이 덜 깨진다.
