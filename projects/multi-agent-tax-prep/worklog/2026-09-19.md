# 2026-09-19 (토) — 라우터 기반 골격

- 전제조건 검사, 되묻기, 검토→기획 사이클, 노드 단위 재시도

## 구조를 이렇게 잡은 이유

에이전트 인계를 `Command` 기반 **대기열**로 처리했다.

```python
def handoff(state, current, updates) -> Command:
    remaining = state["todo_agents"][1:]          # 대기열 맨 앞이 자기 자신
    goto = remaining[0] if remaining else END
    return Command(update={**updates, "todo_agents": remaining, ...}, goto=goto)
```

라우터가 `["research", "planning", "review"]`를 만들면 각 에이전트가 자기를 빼고
다음으로 넘긴다. `add_conditional_edges`나 매핑 딕셔너리가 한 줄도 필요 없다.

실행 순서가 요청마다 달라지는 시스템에선 이 방식이 낫다. 조건부 엣지로 하려면
"조사 다음은?"을 미리 다 열거해야 하는데, 조합이 늘면 감당이 안 된다.

## 설계를 바꾼 지점 두 개

### ① 선형 구조에서 사이클 추가

처음 그린 그래프가 `router → research → planning → review → END` 선형이었다.
"되돌아가는 경로가 없으면 LangChain 체인과 뭐가 다른가"라는 지적을 받고 다시 봤다.

맞는 지적이었다. LangGraph의 강점 중 **사이클을 안 쓰고 있었다.**
검토가 "계획 자체가 잘못됐다"고 판단하면 기획으로 되돌리도록 고쳤다.

무한루프 방지는 두 층으로 뒀다.

| 막는 것 | 방식 |
|---|---|
| 업무 규칙 (되돌리기 1회까지) | State의 `revision_count` |
| 버그 (조건식 실수로 무한루프) | `recursion_limit` |

### ② 전제조건 검사

라우터가 순서를 잘못 잡는 경우를 못 막고 있었다.
"노트북 경비 되나?" 요청에 검토만 실행되면, 상대가 근로소득자인지 사업소득자인지
모른 채 답하게 된다. 근로소득자에게는 필요경비라는 개념 자체가 없는데도.

각 에이전트가 자기 입구에서 전제를 직접 확인하게 했다.
정보가 없으면 조사를 먼저 요청하고 돌아온다.

남을 믿지 않고 자기 입구에서 확인하는 게 맞다.
