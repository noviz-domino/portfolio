# 6단계: 메타 진행 + 결과화면(R2) + 심연모드 + R1~R5 요구사항

## 목표 (기획서 §14-6)
메타 진행(격납고 UI+트리+저장) + 결과화면(R2 점수) + 심연모드 + R1/R3/R4/R5 전체 반영

## 구현 내용

### 메타 진행 — 격납고 (§9)
- **코어 에센스(✧ESS) 획득**: 잡몹 10%확률 1 / 원거리 25%확률 2 / 엘리트 12 / 보스(세라프40·하이브퀸90·특이점200) / 생존보너스 분당8 / 클리어150 — `awardEssence()`에서 킬 시점마다 계산, 런 종료 시 생존·클리어 보너스를 더해 `Meta.essence`에 정산
- **영구 강화 트리 3계통** (`CONFIG.META_TREE`, 10개 노드):
  - HULL: 강화 장갑(+1칸, 최대2) / 위상 코팅 프리셋(무적시간, 최대3) / 비상 리부트(1회 부활, 최대1)
  - ARMS: 표적 보정기(데미지) / 가속 냉각(공속) / 오버드라이브 증폭(요구 게이지 감소)
  - SYS: 자기 코일(흡수범위) / 학습 프로토콜(XP) / 채굴 드론(에센스) / 리롤 칩(런당 레벨업 리롤 횟수)
- 비용 = `baseCost × (다음 레벨)`, 격납고 UI에서 실시간 구매(에센스 부족/MAX 시 버튼 비활성화)
- `applyMetaBonuses()`가 런 시작(`Game.reset()`) 시 모든 노드 효과를 `player.hullMax`, `player.derived`, `player.overdriveThreshold`, `player.rerollsRemaining` 등에 반영
- 레벨업 드래프트에 **리롤 버튼** 추가 — `reroll_chip` 보유 수만큼 카드 3장을 다시 뽑을 수 있음

### 저장 시스템 (§9, §12)
- `localStorage["sd_save_v1"]`에 버전 필드 포함 JSON(에센스, 노드별 레벨, 통계) 저장
- `SaveSystem.load()/save()` 모두 try/catch로 손상·접근 불가 시 `defaultData()` 폴백
- 런 종료·격납고 구매 시점에만 저장(디바운스 없이 이벤트 기반 저장 — §12 요구사항 그대로)
- 격납고에 **초기화 버튼 2단 확인**(첫 클릭 시 "정말 초기화?" 문구로 전환, 4초 내 재클릭해야 실제 초기화, 타임아웃 시 원복)

### 결과화면 R2 점수 공식
- `computeScore()`: `floor(생존시간×10) + 킬수×5 + 엘리트킬×50 + 보스킬×1000 + 그레이즈×2 + 획득에센스×1` — 기획서 공식 그대로 구현
- 결과 화면에 항목별 브레이크다운(각 수치와 배율 표시) + 합계, `Meta.stats.bestScore` 갱신 시 "NEW BEST!" 표시, 아니면 기존 최고 기록 표시

### 승리/패배 조건 (§10)
- **승리**: 특이점 코어 격파 → 즉시 정산 대신 `STATE.CLEAR_CHOICE` 오버레이로 **[탈출(정산)] / [심연으로]** 선택 제공
  - 탈출: 그 자리에서 `finalizeRun('CLEAR')`
  - 심연으로: `Game.abyssMode=true`로 전환해 플레이 계속, 60초마다 `abyssTier` 증가 → 적HP×1.25^tier, 스폰율×1.15^tier, 에센스×1.10^tier 중첩 적용(스폰/난이도 시스템에 배율로 연결)
- **패배**: 코어 무결성 0 도달 시 `emergency_reboot` 보유 & 미사용이면 자동으로 1회 부활(체력2로 복귀, 무적2초), 이미 사용했으면 정상적으로 `finalizeRun('FAILED')`
- 사망 페널티 없음(에센스 100% 유지)은 기존 구조 그대로 — 에센스는 런 종료 시 무조건 정산되어 사망해도 손실 없음

### R1~R5 최종 반영 확인
- **R1**: 메인 메뉴에 조작법 카드 상시 노출 — 기존 구조 유지, 추가 변경 없음
- **R2**: 위 점수 공식 및 브레이크다운 이번 단계에서 완성
- **R3**: FAILED/CLEAR 모두 동일한 `finalizeRun()` 경로로 통일 — 기존 구조 유지, 클리어 시에만 선택지(§10) 단계가 앞에 추가됨
- **R4**: 결과 화면에 `[다시 출격]`(즉시 재도전) / `[격납고로]`(메타 구매 후 출격) 버튼 분리 제공, 두 경로 모두 `Game.reset()`으로 완전 초기화 후 즉시 재진입, 로딩 화면 없음
- **R5**: 모든 신규 버튼(격납고 구매, 리롤, 초기화, 탈출/심연) 리스너도 `UI.init()`에서 **단 한 번만 등록**, `safeTransition()` 재진입 가드는 `startRun()`/`goToHangar()` 모두에 적용됨. 게임 루프는 부팅 시 1회만 시작되는 기존 구조 그대로 유지

## 브라우저 검증 결과
- 콘솔 에러 없음
- 격납고 UI 렌더링 확인(10개 노드, 3열 배치), 에센스 100 지급 후 구매 버튼 활성화 확인
- `metaBuyNode()` 비용 계산·레벨 증가·에센스 차감 정확성 확인, **새로고침 후 `localStorage` 값 그대로 유지**됨을 확인(강화 장갑 Lv1, 가속 냉각 Lv2 유지)
- 메타 보너스가 실제 런에 반영됨을 확인: `armor_plus Lv1` → `player.hullMax=6`, `accel_cooling Lv2` → `fireRateMult=0.9`
- 특이점 코어 처치 → `CLEAR_CHOICE` 오버레이 정상 노출(격리 테스트로 재확인) → `[심연으로]` 클릭 시 `abyssMode=true`, `state='PLAYING'`으로 복귀 확인
- R2 점수 공식 수동 계산(2557) = `computeScore()` 반환값(2557) 정확히 일치 확인, 격납고의 "최고 점수" 갱신 확인, 노드 MAX 도달 시 "MAX" 표기 및 버튼 비활성화 확인
- 비상 리부트: 첫 사망 시 자동 부활(체력2, `rebootUsed=true`) 확인, 두 번째 사망은 정상적으로 FAILED 처리됨을 확인

## 참고
- 심연모드의 60초 티어 증가 타이머는 단순 카운트다운 로직(코드 검토로 충분히 신뢰 가능)이라 실시간 장시간 대기를 통한 재확인은 생략 — 실제 플레이테스트 시 재확인 권장
- 격납고 구매/레벨업 리롤 등 반복 클릭 UI는 테스트 중 브라우저 자동화 특성상 의도치 않은 연속 클릭이 관찰되었으나, 이는 자동화 도구의 타이밍 이슈이며 게임 로직 자체의 결함이 아님을 격리 테스트로 확인함
