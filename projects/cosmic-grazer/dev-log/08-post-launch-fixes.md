# 8단계: 출시 후 피드백 반영 (배경, 오버드라이브 UX, 밸런스, 명예의 전당)

## 배경
계획된 §14 우선순위 7단계가 끝난 뒤, 실제 사용자가 플레이해보고 준 피드백을 반영한 단계입니다. 새 기능 우선순위를 따르기보다 "플레이해보니 아쉬운 점"을 하나씩 고치는 방식으로 진행했습니다.

## 구현 내용

### 1. 배경화면 추가
- 기존에는 단색(`#05070d`) 배경뿐이었음 — "배경화면이 필요할 것 같다"는 요청 반영
- `Starfield`: 3중 패럴랙스 별밭(원거리 저채도 점 → 근거리 밝은 점, 각기 다른 이동 속도)을 화면 좌표계에 렌더링, 타일링 방식으로 카메라가 어디로 이동해도 끊김 없이 이어지도록 구현
- `NEBULA_BLOBS`: 아레나 고정 좌표에 은은한 색상 성운 블롭 3개(방사형 그라디언트)를 배치해 우주적 분위기 강화

### 2. 오버드라이브를 이해하기 어려운 문제
- 최초 문제 제기: "스페이스바를 계속 누르고 있어도 작동하지 않는다"
- 원인 진단: 코드 로직 자체는 정상(격리 테스트로 검증)이었으나, 오버드라이브 게이지가 **그레이즈로만 충전**되는데 이를 안내하는 UI가 없어 게이지가 항상 0인 상태로 눌러본 것으로 파악
- 조치: 메인 메뉴 조작법에 그레이즈→게이지 충전→홀드 발동 흐름을 명시, HUD에 "OD" 라벨과 게이지 충전 완료 시 "READY(홀드)" 텍스트 추가

### 3. 그레이즈 시 대시가 먼저 발동하는 문제
- 문제 제기: "그레이즈를 하면(게이지가 찬 상태에서) 대시가 먼저 발동되고 계속 눌러야 한다"
- 원인: Space를 누르는 즉시 대시가 발동하고, 그 뒤에 홀드 시간을 별도로 누적하는 구조라 오버드라이브를 노리고 누르면 원치 않는 대시가 항상 먼저 나감
- 수정: **탭/홀드 판정 지연 로직** 도입 — 게이지가 오버드라이브 임계치 이상일 때만 Space press 순간 판정을 0.35초 유예. 그 안에 떼면 탭으로 간주해 대시 발동(게이지 유지), 0.35초 이상 유지하면 대시 없이 오버드라이브만 발동. 게이지가 부족할 때는 기존처럼 즉시 대시(반응성 그대로)
- `fixedUpdate`를 직접 반복 호출하는 방식으로 3가지 케이스(게이지 부족 즉시대시 / 게이지 충분+롱홀드→오버드라이브만 / 게이지 충분+짧은탭→대시만) 모두 격리 검증 완료

### 4. HUD 레이아웃 겹침
- 문제: OD 게이지 추가 후 XP바(`position:absolute`, 고정 `top` 값)가 그 위에 겹쳐 보이지 않음
- 1차 수정 시도: XP바를 절대좌표에서 일반 흐름(normal flow)으로 변경 — 그런데 `#hud`가 `justify-content:space-between`인 flex 컨테이너라 남는 공간이 개별 항목 "사이"에 분배되면서 XP바가 화면 중앙까지 밀려버림(2차 문제 제기: "이번엔 너무 중앙에 왔어")
- 최종 수정: 체력칸+OD게이지+XP바+레벨 표시를 `#hudTopGroup`이라는 하나의 래퍼로 묶어 그 자체는 일반 블록 흐름으로 붙어 있게 하고, `#hud`의 flex 자식은 `hudTopGroup`(상단)과 `slotsRow`(하단) 단 둘만 남겨 `space-between`이 이 둘 사이에만 여백을 주도록 구조 변경. 결과적으로 상단 그룹은 서로 겹치지도, 흩어지지도 않고 화면 맨 위에 고정됨

### 5. 밸런스 조정
- **적 탄속**: "적의 탄속이 너무 빠르다" — 원거리 적 4종·오벨리스크·보스 3종의 기본 탄속을 30~45% 하향(예: 스나이퍼 아이 620→360, 세라프-01 조준버스트 420→300), 시간에 따른 탄속 증가 배율도 완화(상한 1.5→1.3, 증가율 0.045→0.025). *(기획서 §7의 1.5 상한 명시값과는 다르나, 실제 플레이 피드백을 우선 반영)*
- **그레이즈 판정 범위**: "아슬아슬하게 스쳐야 하는 범위가 너무 작다" — `GRAZE_RADIUS` 22px → 40px로 확대, 플레이어 주변 참고선 원도 함께 커짐
- **오버드라이브 발동 시 체력 +1**: "그레이즈를 사용하면(오버드라이브 발동 시) 목숨이 1개 늘어나야 할 것 같다" — 오버드라이브 발동 시 코어 무결성 1칸 회복(최대치 초과 불가) 추가. 그레이즈로 쌓은 위험이 화력·파밍뿐 아니라 생존 자원으로도 환원되도록 함

### 6. 명예의 전당 (로컬 랭킹 top 5) — 프로필 기반으로 재설계
최초 구현은 "런이 끝날 때마다 이름을 입력받아 점수를 등록"하는 방식이었으나, 대화 중 사용자가 두 가지 문제를 지적하면서 프로필 개념으로 재설계했다:
- **문제 A**: "결국 격납고 강화를 많이 해둔 사람이 점수를 받기 유리한 게 아니냐" → 이건 로그라이크 메타 진행 구조상 자연스러운 특성으로 판단, 그대로 유지하기로 결정(사용자 확인)
- **문제 B**: "한 세이브로 계속 플레이하면서 매번 다른 이름을 등록해 여러 사람인 척 할 수 있다" → 이건 실제 결함으로 판단, 아래처럼 구조 변경

**재설계 내용**:
- `Meta.pilotName`을 세이브당 1개로 고정. 매 런 결과 화면에서 이름을 새로 입력받는 대신, **게임을 처음 시작할 때 딱 한 번만** 조종사 이름을 등록
- 점수는 더 이상 "런 1회 점수"가 아니라 **그 이름으로 플레이한 모든 런의 누적 총점**(`Meta.totalScore`, 매 런 종료 시 가산)으로 명예의 전당에 반영 — `Leaderboard.upsert()`가 이름당 한 행만 유지하며 갱신(플레이할수록 순위표의 자기 행이 계속 올라가는 구조)
- 다른 이름으로 새로 시작하려면 격납고에서 슬쩍 바꾸는 게 아니라, 플레이 화면의 **"게임 종료" 버튼**(2단 확인)으로 나가야만 가능 — 이 버튼을 누르면 조종사 이름은 물론 격납고 강화 수치·에센스까지 전부 초기화되고 시작 화면으로 돌아감. 즉 "이름을 바꾼다 = 새 프로필로 완전히 다시 시작한다"가 되어, 문제 B가 원천적으로 봉쇄됨

### 7. 시작 화면 전면 재구성 (프로필 온보딩 + 게임종료 버튼)
- 요청: 시작 시 [게임시작]/[명예의 전당] 2개 메뉴 → 게임시작 시 최초 1회 이름 입력 → 조작법 안내 → 격납고 → 플레이. 플레이 화면 우측 상단에 겹치지 않는 "게임 종료" 버튼
- `STATE`에 `START`/`NAME_ENTRY`/`CONTROLS`를 추가하고 화면 흐름을 재편:
  `START(게임시작/명예의전당)` → *(이름 없으면)* `NAME_ENTRY` → `CONTROLS(조작법, R1)` → `HANGAR` → `PLAYING`
- 기존 `menuOverlay`(조작법+시작 버튼 한 화면)를 3개 오버레이(`startOverlay`/`nameEntryOverlay`/`controlsOverlay`)로 분리
- HUD 우측 상단에 "게임 종료" 버튼을 KILL/SCORE 표시 **위쪽**에 세로로 쌓아 배치(같은 우측 정렬 컬럼 안에 버튼 → 점수 순으로 배치) — 다른 UI(체력칸/OD게이지/XP바/타이머)와 겹치지 않음
- `Game.quitToStart()`: 세이브 전체를 `SaveSystem.defaultData()`로 되돌리고(이름·격납고·에센스·명예의전당 통계는 유지, 진행 세이브만 초기화) 시작 화면으로 복귀. "데이터 초기화"(격납고 내 버튼)도 동일하게 시작 화면 복귀로 통일
- 격납고의 기존 "조종사 이름 변경" 필드는 제거(정체성 변경 경로를 "게임종료" 하나로 단일화하기 위함), 대신 조종사 이름·누적 점수를 읽기 전용으로 상단에 표시

## 브라우저 검증 결과
- 콘솔 에러 없음(전 과정)
- 배경 별밭·성운이 카메라 이동에 따라 자연스럽게 시차 이동하는 것을 스크린샷으로 확인
- 오버드라이브 탭/홀드 판정 3가지 시나리오 모두 `fixedUpdate` 직접 호출로 격리 검증(게이지부족→즉시대시 / 게이지충분+롱홀드→오버드라이브만·대시타이머0 / 게이지충분+숏탭→대시만·게이지유지)
- HUD 레이아웃: 체력칸/OD게이지/XP바/레벨/게임종료 버튼이 겹침이나 쏠림 없이 상단에 순서대로 고정됨을 확인
- 오버드라이브 발동 시 체력 3→4 회복, 최대치(5)에서는 더 늘지 않음(캡 정상 동작) 확인
- 신규 온보딩 플로우 전체를 순서대로 실행해 확인: START(이름 없음) → 이름 입력("테스트조종사") → 조작법 확인 → 격납고(조종사 이름 표시 확인) → 출격 → 플레이(게임종료 버튼 노출 확인)
- **격납고 버튼 소실 버그 발견 및 수정**: `#hangarTree`의 닫는 태그 누락으로 초기화/출격 버튼이 그 안에 중첩되어 있었고, `renderHangar()`가 `innerHTML`을 덮어쓰면서 매번 버튼이 사라지는 실제 버그를 발견 — 태그 구조 수정으로 해결, 이후 버튼 정상 존재 확인
- 게임종료 버튼 2단 확인 확인: 1차 클릭 시 "정말 종료? (다시 클릭)"로 텍스트 전환, 2차 클릭 시 `Meta.pilotName`/`essence` 등 전체 초기화 및 START 화면 복귀 확인
- 누적 점수 시스템 확인: 같은 조종사로 2회 연속 런(FAILED) 진행 시 `Meta.totalScore`가 정확히 누적(555 → 1446)되고, 명예의 전당에는 중복 행 없이 같은 이름의 행이 계속 갱신(`runsPlayed` 1→2)됨을 확인
- 결과 화면에 "누적 점수(명예의 전당 기준)"과 "🏆 명예의 전당 갱신!" 배너가 정확한 이름·누적점수로 표시됨을 스크린샷으로 확인

## 참고
- 이번 단계의 문제 상황 다수는 **브라우저 자동화 도구 자체의 클릭 재생/타이밍 아티팩트**(지연된 클릭이 나중 화면에 잘못 도착)로 인해 스크린샷 검증이 매끄럽지 않았음 — 실제 로직은 `fixedUpdate()` 직접 호출이나 DOM 상태 즉시 조회로 이중 검증해 신뢰성 확보
- 탄속 상한을 기획서 명시값(1.5)에서 1.3으로 낮춘 것은 실제 플레이 피드백을 우선한 의도적 이탈 — 추후 다시 올리고 싶다면 `CONFIG.DIFFICULTY.bulletSpeedMult()` 한 곳만 수정하면 됨
- "격납고 강화가 점수에 유리하게 작용하는 것"은 사용자 확인 하에 의도적으로 유지 — 다만 프로필(이름) 단위로 명확히 귀속되므로, 명예의 전당은 이제 "누가 이 세이브에 가장 많은 시간/실력을 투자했는가"를 보여주는 지표로 일관성 있게 해석 가능
