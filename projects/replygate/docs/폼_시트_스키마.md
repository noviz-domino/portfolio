# 구글 폼 질문 구성 · 시트 스키마

> 이 문서대로 만들면 n8n 노드 매핑과 Apps Script 대안이 그대로 맞물린다.
> **헤더 이름은 절대 바꾸지 말 것.** n8n Sheets 노드와 Apps Script가 컬럼명으로 값을 찾는다.

---

## 1. 구글 폼 구성

**폼 제목:** 온마켓 고객문의
**설명:** 문의 주신 내용은 담당자 확인 후 입력하신 이메일로 답변드립니다. 평균 응답 시간은 1영업일입니다.

| # | 질문 제목 | 유형 | 필수 | 비고 |
|---|---|---|---|---|
| 1 | `이름` | 단답형 | ✅ | 답변 인사말에 사용 |
| 2 | `이메일` | 단답형 | ✅ | **응답 확인 → 이메일 형식** 유효성 검사 설정 |
| 3 | `주문번호` | 단답형 | ✖ | 선택. "모르시면 비워두세요" 안내 |
| 4 | `문의내용` | 장문형 | ✅ | AI 분류·초안 생성의 입력 |
| 5 | `개인정보 수집 동의` | 체크박스 | ✅ | 항목 1개: "답변 발송을 위한 이메일 수집에 동의합니다" |

**질문을 4~5개로 제한한 이유:** 발표장에서 청중이 QR로 참여하는데 문항이 많으면 이탈한다. 문의 유형은 **일부러 묻지 않는다** — AI가 분류하는 것이 이 시스템의 기능이기 때문이다.

### 폼 설정

- 설정 → 응답 → **이메일 주소 수집: 사용 안 함** (직접 입력받으므로 중복)
- 설정 → 응답 → 응답 사본 전송: 사용 안 함
- 설정 → 프레젠테이션 → 확인 메시지: *"접수되었습니다. 입력하신 이메일로 답변드리겠습니다."*
- 응답 탭 → 스프레드시트 아이콘 → **새 스프레드시트 만들기** → 이름 `ReplyGate_운영`

## 2. 시트 구성

스프레드시트 `ReplyGate_운영` 안에 시트 3개를 둔다.

| 시트명 | 용도 |
|---|---|
| `문의` | 폼 응답 + AI 처리 결과. **메인 테이블** |
| `조항` | RAG 적재용 정책 조항 (n8n이 읽어서 벡터화) |
| `평가셋` | 평가셋 50건과 측정 결과 |

> 폼과 연결하면 시트 이름이 `설문지 응답 시트1` 로 생성된다. **`문의` 로 이름을 바꿔도 연결은 유지**된다.

---

## 3. `문의` 시트 스키마

폼이 만드는 컬럼(A~F)의 **오른쪽에** 워크플로우용 컬럼을 추가한다.
구글 폼은 새 응답을 A열부터 채우므로, 오른쪽에 추가한 열은 밀리지 않고 유지된다.

| 열 | 컬럼명 | 생성 주체 | 설명 |
|---|---|---|---|
| A | `타임스탬프` | 폼 | 제출 시각 (자동) |
| B | `이름` | 폼 | |
| C | `이메일` | 폼 | |
| D | `주문번호` | 폼 | 비어 있을 수 있음 |
| E | `문의내용` | 폼 | |
| F | `개인정보 수집 동의` | 폼 | |
| G | `inquiry_id` | n8n | `INQ-20260801-001` 형식 |
| H | `category` | AI (P1) | 환불/배송/교환반품/불량AS/회원적립금/기타 |
| I | `sentiment` | AI (P1) | 불만/일반 |
| (U) | `needs_lookup` | AI (P1) | `TRUE`/`FALSE` — 주문 조회가 필요한 문의인지. **선택 컬럼**이며 대시보드 집계용. 없어도 카드 배지는 정상 동작 |
| J | `summary` | AI (P1) | 한 문장 요약 |
| K | `search_query` | AI (P1) | RAG 검색용 정규화 문장 |
| L | `cited_clauses` | AI (P2) | `RF-02,RF-13` 쉼표 구분 |
| M | `insufficient_info` | AI (P2) | `TRUE`/`FALSE` — 환각 탐지용 |
| N | `draft_id` | n8n | Gmail Draft ID |
| O | `revision_count` | n8n | 수정 요청 횟수 (초기 0) |
| P | `status` | n8n | 아래 상태값 참조 |
| Q | `status_at` | n8n | 마지막 상태 변경 시각 — **실시간 상황판의 정렬 기준** |
| R | `sent_at` | n8n | 발송 시각 |
| S | `final_body` | n8n | 최종 발송 본문 |
| T | `handler_note` | n8n | 마지막 수정 지시 원문 (감사 기록) |

### 상태값

| status | 의미 | 다음 상태 |
|---|---|---|
| `접수됨` | 폼 제출 감지 직후 | → `분석중` |
| `분석중` | P1 분류 + RAG 검색 진행 중 | → `승인대기` |
| `승인대기` | 초안 생성 완료, 텔레그램 카드 발송함 | → `발송완료` 또는 `수정중` |
| `수정중` | 담당자가 수정 요청, 재생성 진행 중 | → `승인대기` |
| `발송완료` | 실제 메일 발송 완료 | (종료) |
| `처리실패` | AI 호출 또는 발송 실패 | 수동 확인 필요 |

> **`status` 와 `status_at` 두 컬럼이 실시간 상황판의 전부다.** FastAPI가 이 두 값만 1~2초마다 읽어서 카드의 위치와 색을 바꾼다. n8n이 각 단계 진입 시 이 두 값만 갱신하면 된다.

## 4. `조항` 시트 스키마

`docs/정책문서.md` 의 조항 70개를 여기에 옮겨 담는다. n8n이 이 시트를 읽어 임베딩하고 벡터 스토어에 적재한다.

| 열 | 컬럼명 | 예시 |
|---|---|---|
| A | `clause_id` | `RF-02` |
| B | `doc` | `환불 정책` |
| C | `title` | `환불 처리 소요 기간` |
| D | `text` | `환불 승인 후 영업일 기준 3일 이내에 결제 수단으로 환급됩니다. ...` |

**임베딩 대상 텍스트는 `title + text` 를 합친 문자열**로 한다. 제목만으로는 정보가 부족하고, 본문만으로는 맥락이 약하다.

## 5. `평가셋` 시트 스키마

| 열 | 컬럼명 | 설명 |
|---|---|---|
| A | `eval_id` | `EV-01` |
| B | `문의내용` | 평가용 문의 원문 |
| C | `정답_category` | 사람이 라벨링한 정답 |
| D | `정답_sentiment` | 사람이 라벨링한 정답 |
| E | `정답_조항` | 근거로 인용해야 맞는 조항 ID |
| F | `함정여부` | `TRUE` = 정책에 답이 없는 문항 |
| G | `난이도` | `단일조항` / `복수조항` / `정보없음` |
| H~ | `측정_*` | 측정 회차별 결과를 오른쪽으로 추가 |

## 6. n8n 매핑 시 주의

1. **컬럼명이 곧 키다.** Sheets 노드는 헤더 문자열로 값을 찾으므로 한 글자라도 바뀌면 매핑이 깨진다.
2. **`문의내용` 은 줄바꿈을 포함한다.** Code 노드에서 다룰 때 개행 처리에 주의한다.
3. **`insufficient_info` 는 시트에서 문자열 `TRUE`/`FALSE` 로 저장된다.** 불리언으로 비교하지 말고 문자열로 비교하거나 명시적으로 변환한다.
4. **행 번호로 접근하지 말고 `inquiry_id` 로 찾는다.** 폼 응답이 동시에 여러 건 들어오면 행 번호가 어긋난다.
5. Apps Script 대안을 쓸 경우 `e.namedValues` 의 키는 **폼 질문 제목과 정확히 일치**해야 한다 (`CLAUDE.md` 참조).

---

## 7. 만드는 순서

1. 구글 폼 생성 → 질문 5개 입력
2. 응답 → 스프레드시트 연결 → 이름 `ReplyGate_운영`
3. 시트 이름을 `문의` 로 변경
4. G~T 열에 헤더 입력 (위 표 그대로)
5. `조항`, `평가셋` 시트 추가
6. 폼을 1회 제출해서 A~F에 값이 들어오고 G 이후 열이 밀리지 않는지 확인 ← **여기서 D1 체크리스트 5번(Sheets 트리거 지연) 측정을 함께 진행**
