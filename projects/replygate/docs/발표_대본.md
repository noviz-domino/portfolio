## 한 줄 주장

> **AI를 빠르게 만드는 것보다, 통제 가능하게 만드는 것이 실무의 문제다.**

발표 전체가 이 문장 하나를 증명하는 구조다. 마지막에 다시 꺼낸다.

## 1. 문제 (1:30)

### 열기 — 말보다 화면

슬라이드에 **베이스라인이 실제로 쓴 답변**을 띄운다. 설명하기 전에 읽게 둔다.

> *"지연에 대한 보상으로 온마켓에서 현금처럼 사용하실 수 있는 **적립금 5,000원을 지급해 드렸습니다.**"*
> — 베이스라인 `EV-17`

**세 가지를 짚는다.**

1. 정책상 보상은 **주문 금액의 5%** 다 (DL-07). 5,000원이라는 금액은 **어디에도 없다**
2. *"지급해 드렸습니다"* — **과거형**이다. 하지도 않은 일을 했다고 말했다
3. 문장이 자연스럽다. **읽는 사람이 틀린 줄 모른다**

### 이게 왜 사고인가

한 건 더 보여준다. 이쪽이 손해가 더 크다.

| 사례 | 무슨 말을 했나 | 실제 |
|---|---|---|
| `EV-42` | 소멸된 적립금을 *"전액 복구 조치될 예정"* | 정책상 **복원 불가** (MB-07) |
| `EV-50` | *"오늘 중 위약금 면제 처리 완료"* + *"가입 당시 안내가 누락되어"* | **회사 귀책을 AI가 인정** |

> **"오타가 아니라 분쟁입니다. 그리고 이 답변들은 아무도 검토하지 않으면 그대로 고객에게 갑니다."**

### 그렇다고 사람이 다 쓰면

문의 한 건에 5~10분. 반복 유형이 대부분인데 매번 규정을 찾는다. 자동화의 의미가 없다.

## 2. 해결 구조 (1:30)

```
AI 초안 생성  →  사람의 검토·승인  →  최종 발송
```

**아키텍처 한 장** — 고객(폼) → 시트 → n8n(분류·RAG·생성) → Gmail 초안 → 텔레그램 카드 → 승인 → 발송.

### 설계에서 강조할 것 세 가지

**① 승인 창구는 텔레그램 하나다.**
웹에서도 승인할 수 있게 만들 수 있었지만 **일부러 안 만들었다.** 만드는 순간 *"휴대폰만으로 완결된다"* 는 차별점이 스스로 무너진다.

**② 근거를 카드에 같이 띄운다.**
초안이 인용한 조항 ID를 함께 보여줘 담당자가 **3초 만에 검증**한다. 이게 없으면 승인은 형식이 된다.

**③ n8n과 대시보드는 직접 통신하지 않는다.**
구글 시트를 공용 저장소로 두고 양쪽이 각각 읽고 쓴다. 덕분에 **외부 공개 URL이 필요 없고**, 오늘 이 자리에서 네트워크 하나가 죽어도 데모 전체가 죽지 않는다.

> 운영 비용 **0원**. n8n · Gemini · Sheets · Gmail · Telegram 전부 무료 티어.

## 3. 라이브 데모 (4:00) ★

### 사전 준비 (발표 전에 끝내둘 것)

- [ ] 대시보드 실행 + 브라우저 전체화면, **발표 모드 토글 ON** (이메일 가림)
- [ ] 텔레그램 앱을 화면 공유에 띄울 준비 (또는 휴대폰 미러링)
- [ ] 시트 리허설 행 삭제 (**1행 헤더는 절대 삭제 금지**)
- [ ] Gmail 임시보관함 비우기
- [ ] 폼 QR 코드 슬라이드 준비
- [ ] **백업용 문의 1건을 미리 제출해 `승인대기` 상태로 대기시켜 둔다** ← 아래 참조

### 진행

**① 청중 참여 (0:30)**
QR로 폼 접속 → **2~3명만** 제출하도록 유도한다.

> RPM 15 제약이라 분당 7~8건이 상한이다. *"많이 넣으면 큐가 밀립니다"* 라고 웃으며 제한하면 자연스럽다.

**② 상황판 (0:30)**
무대 화면의 대시보드에서 카드가 `접수됨 → 분석중 → 승인대기` 로 흐른다.

> Sheets 폴링이라 **최대 1분** 걸린다. 이 시간에 ②의 설명을 채운다 — 지금 뒤에서 무슨 일이 일어나는지(분류 → 정책 검색 → 초안 생성 → Gmail 초안 저장).

**③ 텔레그램 카드 (1:00)**
휴대폰 화면을 보여준다. 카드에서 짚을 것:

- `🔴/⚪` 감정 배지, `📋` 주문 조회 필요 배지 — **두 개가 동시에 뜨는 조합**을 가리킨다
- `📎 근거: DL-04, DL-06` — 담당자가 검증할 지점
- `💬 고객 문의` — 원문이 그대로 실려 있다

> **"이 두 배지는 원래 하나로 묶여 있었습니다. 나중에 왜 쪼갰는지 말씀드리겠습니다."** ← ④로 넘기는 복선

**④ 승인 (0:30)**
`✅ 발송 승인` → 완료 알림 → 상황판 카드가 `발송완료` 로 이동.

> *"지금 메일함을 확인해보세요."* — 청중이 직접 받은 걸 확인하게 한다.

**⑤ 수정 루프 + 정책 충돌 (1:30)** ★ 가장 강한 장면
다른 한 건에서 `✏️ 수정 요청` → **일부러 정책과 다른 지시**를 넣는다.

```
무료배송 기준이 3만원이라고 안내해줘
```

재검토 카드에 `⚠️ 지시와 정책이 충돌합니다` 가 뜬다. 문제 문장과 `[DL-02] … 50,000원 이상 무료배송` 원문이 나란히 나온다.

> **"AI의 실수는 사람이 막고, 사람의 실수는 AI가 잡습니다. 양방향입니다."**
>
> 이어서: **"막지는 않습니다.** 담당자가 예외 승인이나 신규 프로모션을 반영할 수도 있으니까요. 경고만 띄우고 **판단은 사람에게 남깁니다.** 아직 아무것도 발송되지 않았고, 승인 버튼이 이미 안전망이니까요."

이 건은 **승인하지 않고** 넘어간다.

### 데모가 안 될 때 (미리 정해둘 것)

| 상황 | 대응 |
|---|---|
| 폼 → 카드가 1분 넘게 안 옴 | **미리 대기시켜둔 백업 건**으로 진행. *"먼저 들어온 건으로 보겠습니다"* |
| Gemini 429 | RPD 500이라 여유는 있으나 **리허설을 발표 직전에 몰아서 하지 말 것.** 터지면 백업 건의 카드로 승인/수정만 시연 |
| 텔레그램이 안 옴 | 대시보드 **카드 상세**로 대체. 문의 원문·초안·근거 조항 원문이 전부 보인다 |
| 대시보드 시트 조회 실패 | **마지막 성공 값으로 화면이 유지된다.** 상단에 경고만 뜨므로 그냥 진행 |
| n8n 실행 실패 | 당황하지 말고 **④ 측정 파트로 넘어간다.** 발표의 결론은 데모가 아니라 숫자다 |

> **데모는 보조다.** 숫자가 결론이라는 것을 스스로 기억해두면 사고가 나도 흔들리지 않는다.

## 4. 측정 — 효과가 있었나 (2:30) ★ 차별점

### 실험 설계 한 줄

평가셋 **50건**을 두 조건으로 각각 돌렸다. **베이스라인**(정책 없이 일반 지식) vs **RAG**(정책 조항 검색 후 생성).

### 결과

```
1차 승인률     RAG 94.0%  vs  베이스라인 34.0%     ← 주 지표
수치 정확률    RAG 96.0%  vs  베이스라인 43.8%     (오류 2개 vs 20개)
```

**1차 승인률 = 수정 없이 그대로 발송 가능한 초안의 비율.** 100줄을 실무 기준(정책 위반 · 사실 창작 · 근거 없는 확약 · 질문 미응답)으로 사람이 판정했고 **판정 근거를 100줄 전부 기록**했다.

### 짚어야 할 두 가지 (여기가 진짜 차별점)

**① 이 지표는 수치 정확률의 재탕이 아니다.**

X 36건 중 **21건은 수치 오류가 아닌** 사유였다 — 근거 없는 확약, 원인 창작, 정책 정면 위반.

> *"숫자를 안 틀려도 승인할 수 없는 답변이 있습니다. 조사도 안 하고 '택배사 과실입니다' 라고 쓰는 것 같은."*

**② 베이스라인이 34%나 나온 이유.**

`EV-37` 은 수리 기간 7~14일을 정책 없이 맞혔다.

> *"AI가 아무것도 못 맞춘 게 아닙니다. **일반 상식과 이 회사 정책이 우연히 겹칠 때만** 맞았습니다. 그게 34%입니다."*

### 감정 분류 — 측정이 설계를 바꾼 이야기 (여유 있으면 여기 시간을 쓴다)

| 시도 | 감정 정확도 | 문제 |
|---|---|---|
| v1 · 3단계 | 56.0% | `중립` **0/20** — 한 번도 안 골랐다 |
| v2 · 정의 개정 | 84.0% | `중립` **0/7** — 여전히 0 |
| **v3 · 두 축 분리** | **98.0%** | — |

**v2를 숨기지 않는 것이 핵심이다.**

> *"정의를 다듬어 56%에서 84%로 올렸습니다. 개선처럼 보이지만 **아닙니다.** 라벨을 모델이 이미 답하던 쪽으로 옮겨서 오른 숫자였고, 중립은 여전히 0이었습니다. 이걸 개선이라고 보고했으면 자기기만입니다."*
>
> *"클래스별로 쪼개봤기 때문에 0/7을 발견했고, 거기서 진짜 원인에 도달했습니다. **감정과 조회 필요 여부는 직교하는 두 축인데 하나의 enum에 눌러 담았던 것**입니다. 모델이 중립을 못 고른 게 아니라 **고를 수 없는 구조**였습니다."*

→ 두 축으로 분리하니 감정 98%, 조회필요 92%. 그리고 쓰이지 않던 클래스가 **`📋` 배지라는 실제 기능**을 갖게 됐다 — 아까 카드에서 본 그 배지다. (복선 회수)

### 한계도 먼저 말한다

`EV-12` — 함정 문항에서 RAG가 `insufficient_info=true` 를 **정확히 달아놓고 본문에서는** *"기프트카드로 환급됩니다"* 라고 단정했다.

> *"함정 회피가 플래그 기준으로는 5/5인데 **본문 기준으로는 4/5** 입니다. RAG를 붙였다고 환각이 사라지지 않습니다. 그래서 사람 승인을 뺄 수 없습니다."*

**이 슬라이드가 발표에서 가장 방어가 강한 지점이다.** 한계를 먼저 말하면 질문이 공격이 아니라 대화가 된다.

## 5. 배운 것 (0:30)

**하나 — 측정하지 않았으면 쓰이지 않는 클래스를 그대로 안고 발표했을 것이다.**

**둘 — 사람은 언제든 과거 UI를 다시 만진다.**
발송이 끝난 건의 옛 텔레그램 카드에서 수정 버튼을 눌렀더니 그대로 먹혔다. 승인 경로에는 중복 방어를 넣었는데 **수정 경로에는 빠뜨렸다.** 그대로 승인했으면 같은 고객에게 메일이 두 번 나갔다. 정상 경로만 따라가는 검증으로는 안 나오는 결함이다.

### 닫는 말

> **"AI를 빠르게 만드는 것보다, 통제 가능하게 만드는 것이 실무의 문제입니다."**
> **"통제 가능하게 만들면서도 실제로 빨라졌는지를 숫자로 확인했습니다. 94% 대 34%입니다."**

## 예상 질문과 답

| 질문 | 답의 뼈대 |
|---|---|
| **사람이 승인해야 하면 자동화가 맞나?** | 담당자가 하는 일이 *"백지에서 5~10분 작성"* 에서 *"읽고 버튼 누르기"* 로 바뀐다. 1차 승인률 94%면 **10건 중 9건은 읽고 누르기만** 하면 끝난다 |
| **왜 AI Agent를 안 썼나?** | 파이프라인 순서가 고정돼 있어 **판단할 게 없다.** 에이전트를 쓰면 매 실행마다 경로가 달라지고 토큰을 더 쓰고 데모가 예측 불가능해진다. 얻는 것 없이 잃는다. 진짜 에이전시가 맞는 자리는 담당자가 *"이 고객 예전에도 문의했어?"* 처럼 자유 질문을 할 때다 |
| **정책이 70개뿐인데 RAG가 필요한가?** | 실제 쇼핑몰은 150~200 조항이다. 그리고 RAG를 쓴 두 번째 이유는 **근거 추적** — 어느 조항을 봤는지 남아야 담당자가 검증하고 지표를 잴 수 있다 |
| **1차 승인률은 누가 판정했나? 주관적이지 않나?** | 실무 기준 네 가지로 좁혔고(정책 위반·사실 창작·근거 없는 확약·질문 미응답), 어조나 군더더기는 통과시켰다. **100줄 전부에 판정 근거를 남겼다.** 기준을 되짚을 수 없으면 지표를 신뢰할 수 없다 |
| **모델은 왜 그걸 골랐나?** | 무료 티어 RPD가 결정적이었다. 정식 Flash 계열은 **하루 20건**이라 평가셋 실험이 불가능했다. Lite 계열(500)로 좁힌 뒤 **두 후보를 실측 비교**했고, 3.1 Lite가 정책에 없는 *"국내 배송만 지원"* 을 창작해서 3.5 Lite로 확정했다. 제약 → 실험 → 선택 |
| **동시에 여러 건을 수정하면?** | **알려진 한계다.** 담당자 텍스트가 어느 문의 것인지 `수정중` 중 가장 최근 건으로 추정한다. 근본 해결은 텔레그램 답장(reply)으로 원본 메시지를 특정하는 것이고, 현재는 안내 메시지에 `[INQ-...]` 를 표시해 눈으로 확인 가능하다 |
| **발송된 걸 또 수정하면?** | 막힌다. `🚫 이미 발송된 건입니다`. 처음엔 안 막혔고 그래서 고쳤다 (§5) |
| **비용은?** | 0원. 다만 무료 티어 한도 안에서다 — 문의 250건/일이 상한 |
| **정책이 바뀌면?** | `조항` 시트를 고치고 적재 워크플로우를 한 번 돌리면 끝난다. 프롬프트를 건드릴 필요가 없다 |
