# ReplyGate 셋업 가이드

> 워크플로우 JSON을 붙여넣기 **전에** 이 문서의 순서대로 준비해야 한다.
> 자격증명이 없으면 JSON을 import해도 노드가 전부 빨간 느낌표로 뜬다.

---

## A. 구글 폼 · 시트 만들기

### A-1. 폼 생성

1. <https://forms.google.com> → 빈 양식
2. 제목 `온마켓 고객문의`, 설명 `문의 주신 내용은 담당자 확인 후 입력하신 이메일로 답변드립니다.`
3. 질문 5개를 **제목까지 정확히** 아래대로 입력

| 질문 제목 | 유형 | 필수 |
|---|---|---|
| `이름` | 단답형 | ✅ |
| `이메일` | 단답형 → 우측 ⋮ → **응답 확인** → 텍스트 → 이메일 | ✅ |
| `주문번호` | 단답형 | ✖ |
| `문의내용` | 장문형 | ✅ |
| `개인정보 수집 동의` | 체크박스, 항목 1개 `답변 발송을 위한 이메일 수집에 동의합니다` | ✅ |

4. 설정 탭 → 응답 → **이메일 주소 수집: 사용 안 함** (직접 입력받으므로 중복)

### A-2. 시트 연결

1. 응답 탭 → 초록색 스프레드시트 아이콘 → **새 스프레드시트 만들기** → 이름 `ReplyGate_운영`
2. 생성된 시트 탭 이름 `설문지 응답 시트1` → **`문의`** 로 변경 (연결은 유지됨)
3. **G1~T1 셀에 헤더 입력.** `docs/폼_시트_스키마.md` 3절의 표를 그대로 옮긴다

```
G1: inquiry_id    H1: category      I1: sentiment          J1: summary
K1: search_query  L1: cited_clauses M1: insufficient_info  N1: draft_id
O1: revision_count P1: status       Q1: status_at          R1: sent_at
S1: final_body    T1: handler_note
```

4. 하단 `+` 로 시트 2개 추가 → **`조항`**, **`평가셋`**
5. `조항` 시트 A1~E1 헤더

```
A1: clause_id   B1: doc   C1: title   D1: text   E1: embedding
```

6. `docs/정책문서.md` 의 조항 70개를 A~D열에 채운다. **E열(embedding)은 비워둔다** — 적재 워크플로우가 채운다
7. **스프레드시트 ID를 메모해둔다.** URL의 `/d/` 와 `/edit` 사이 문자열이다

```
https://docs.google.com/spreadsheets/d/★이_부분이_ID★/edit
```

### A-3. 폼 1회 제출 (D1 체크리스트 5번)

폼을 실제로 한 번 제출하고 **A~F열에 값이 들어오는지, G열 이후가 밀리지 않는지** 확인한다.
구글 폼은 A열부터 채우므로 오른쪽에 추가한 열은 유지된다.

## B. 구글 자격증명 (Sheets · Gmail 공통)

n8n에서 구글 서비스를 쓰려면 Google Cloud에 OAuth 클라이언트가 필요하다. **한 번 만들면 Sheets와 Gmail 양쪽에 재사용**할 수 있다.

### B-1. Google Cloud 프로젝트 준비

1. <https://console.cloud.google.com> → 프로젝트 만들기 (이름 `replygate`)
2. **API 및 서비스 → 라이브러리** 에서 아래 두 개를 검색해 **사용 설정**
   - `Google Sheets API`
   - `Gmail API`

### B-2. OAuth 동의 화면

1. **API 및 서비스 → OAuth 동의 화면**
2. User Type: **외부** → 만들기
3. 앱 이름 `ReplyGate`, 사용자 지원 이메일·개발자 이메일 입력
4. 범위 추가 화면에서 아래를 추가

| 스코프 | 용도 |
|---|---|
| `https://www.googleapis.com/auth/spreadsheets` | 시트 읽기·쓰기 |
| `https://www.googleapis.com/auth/gmail.modify` | **초안 생성 + 초안 발송** |

> **Gmail 스코프가 핵심이다.** `gmail.modify` 하나로 초안 생성(`drafts.create`)과 초안 발송(`drafts.send`)이 모두 커버된다. 별도로 `gmail.send` 를 넣지 않아도 되지만, D1 체크리스트 6번에서 **실제로 두 동작을 다 테스트해서 확인**할 것.

5. 테스트 사용자에 **본인 구글 계정을 반드시 추가.** 안 하면 인증 시 `403 access_denied` 가 난다

### B-3. OAuth 클라이언트 ID

1. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
2. 애플리케이션 유형: **웹 애플리케이션**
3. **승인된 리디렉션 URI** 에 n8n이 알려주는 주소를 넣는다
   - n8n → Credentials → New → `Google Sheets OAuth2 API` 선택 → 화면에 표시되는 **OAuth Redirect URL** 을 복사
   - n8n Cloud라면 보통 `https://<계정>.app.n8n.cloud/rest/oauth2-credential/callback` 형태
4. 만들기 → **클라이언트 ID와 보안 비밀번호**를 복사

### B-4. n8n 자격증명 등록

| n8n 자격증명 | 넣을 값 |
|---|---|
| `Google Sheets OAuth2 API` | 위의 클라이언트 ID / 시크릿 → **Sign in with Google** |
| `Gmail OAuth2 API` | **같은** 클라이언트 ID / 시크릿 → **Sign in with Google** |

Sheets Trigger 노드는 `Google Sheets Trigger OAuth2 API` 라는 별도 자격증명을 요구할 수 있다. 같은 값으로 하나 더 만들면 된다.

### B-5. Gmail 동작 테스트 (D1 체크리스트 6번)

n8n에서 Gmail 노드 하나를 임시로 만들어 두 동작을 순서대로 확인한다.

1. **Resource: Draft / Operation: Create** → To에 본인 주소, Subject·Message 아무 값 → 실행 → 출력의 `id` 복사
2. **Resource: Draft / Operation: Send** → Draft ID에 위 값 → 실행 → 메일함에 도착 확인

**둘 다 성공해야 통과다.** 1번만 되고 2번이 실패하면 스코프가 부족한 것이므로 B-2로 돌아가 `https://mail.google.com/` 을 추가하고 자격증명을 다시 인증한다.

## C. 텔레그램 봇 · 인라인 버튼

### C-1. 자격증명

1. BotFather에서 발급받은 토큰 (노출됐다면 **Revoke 후 새 토큰**)
2. n8n → Credentials → New → `Telegram API` → Access Token에 붙여넣기

### C-2. 내 chat_id 알아내기

봇에게 아무 메시지나 보낸 뒤 PowerShell에서:

```bash
Invoke-RestMethod "https://api.telegram.org/bot토큰/getUpdates"
```

응답의 `message.chat.id` 가 담당자 chat_id다. 워크플로우에서 이 값으로 카드를 보낸다.

> 봇에게 먼저 말을 걸지 않으면 봇이 나에게 메시지를 보낼 수 없다. **텔레그램은 사용자가 먼저 대화를 시작해야 한다.**

### C-3. 인라인 버튼 보내기 (Telegram 노드)

- **Resource:** Message / **Operation:** Send Message
- **Chat ID:** C-2에서 얻은 값
- **Text:** 카드 본문
- **Reply Markup:** `Inline Keyboard` 선택
- **Inline Keyboard → Add Row → Add Button** 을 두 번

| 버튼 | Text | Additional Fields → Callback Data |
|---|---|---|
| 1 | `✅ 발송 승인` | `approve:{{ inquiry_id }}` |
| 2 | `✏️ 수정 요청` | `revise:{{ inquiry_id }}` |

> **Callback Data에 `inquiry_id` 를 반드시 실어야 한다.** 콜백이 도착했을 때 어떤 문의에 대한 승인인지 알 방법이 이것뿐이다. 텔레그램 규격상 **64바이트 제한**이 있으므로 긴 문자열은 넣을 수 없다.

### C-4. 콜백 수신 (Telegram Trigger)

- **Trigger On** 목록에서 **`Callback Query`** 를 체크 (기본값에서 빠져 있다)
- 텍스트 수정 지시도 받아야 하므로 **`Message`** 도 함께 체크

수신 데이터는 이렇게 들어온다.

```
{{ $json.callback_query.data }}       → "approve:INQ-20260801-001"
{{ $json.callback_query.from.id }}    → 누른 사람 chat_id
{{ $json.callback_query.id }}         → answerCallbackQuery 에 필요
{{ $json.callback_query.message.message_id }} → 카드 수정용
```

### C-5. answerCallbackQuery — 빠뜨리면 먹통처럼 보인다

버튼을 누르면 텔레그램 앱에 **로딩 원이 계속 돈다.** 이걸 멈추려면 응답을 보내야 한다.

- Telegram 노드 → **Resource: Callback / Operation: Answer Query**
- **Query ID:** `{{ $json.callback_query.id }}`
- **Text:** `처리 중입니다...`

**콜백을 받은 직후, 다른 처리보다 먼저** 이 노드를 두는 것이 요령이다. 기능은 멀쩡한데 사용자 눈에는 고장 난 것처럼 보이는 게 데모에서 가장 나쁘다.

### C-6. 테스트 (D1 체크리스트 4번)

1. Telegram Trigger + Send Message(인라인 버튼) 만 있는 임시 워크플로우를 만든다
2. Activate 후 버튼이 달린 메시지를 자신에게 보낸다
3. 버튼을 누른다
4. n8n 실행 기록에서 `callback_query.data` 에 `approve:TEST01` 이 들어왔는지 확인

- [ ] `조항` 시트에 조항 70개 (A~D열)
- [ ] Google Sheets 자격증명 (+ Trigger용)
- [ ] Gmail 자격증명, Draft 생성·발송 둘 다 테스트 통과
- [ ] Telegram 자격증명
- [ ] 담당자 chat_id
- [ ] Gemini API 키
- [ ] `callback_query` 수신 확인
