## 한 줄 요약

Google Forms로 들어온 고객 문의를 Gemini가 사내 정책 문서(RAG)를 근거로 답변 초안을 쓰고, 담당자가 텔레그램 인라인 버튼으로 승인·수정한 뒤에만 Gmail로 발송되는 **Human-in-the-Loop 고객 응대 시스템**.

- 부트캠프: 멀티캠퍼스 AI에이전트 엔지니어 트랙 **2주차 미니프로젝트**
- 개인 / 7일 / 발표는 2026-08-07~08 예정 (작성일 2026-08-01)
- 적용 도메인: **이커머스 쇼핑몰 CS**

### 발표에서 쓸 자산

1. **RAG의 환각 차단 증거** — 베이스라인 `EV-17`이 *"적립금 5,000원을 지급해 드렸습니다"* 라고 **금액을 지어내고 과거형으로 단정**했다. 정책(DL-07)은 주문 금액의 5% 적립. `EV-01`은 환불 기한을 14일 → 7일로 축소 안내
2. **감정 분류 3회차 측정 기록** — `측정결과_v1_구정의.md`(56%, 중립 0/20) → `_v2_정의개정.md`(84%, 중립 0/7, **라벨만 옮긴 가짜 개선**) → `측정결과.md`(두 축 분리, 98%). **v2를 숨기지 않는 것이 핵심.** 클래스별로 쪼개 봤기에 0/7을 발견했고 구조 문제에 도달했다
3. **모델 비교 실험** — `eval/모델비교_결과.md`. `gemini-3.1-flash-lite` 가 정책에 없는 *"국내 배송만 지원"* 을 창작
4. **정책 충돌 감지 데모** — 무대에서 정책과 다른 지시를 넣으면 ⚠️ 경고가 뜬다
5. **두 배지 동시 표시** — ⚪ + 📋 조합은 3단계 enum에서 표현 불가능했던 케이스
6. **1차 승인률 94.0% vs 34.0%** — 주 지표. X 36건 중 **21건은 수치 오류가 아닌** 사유였다 (근거 없는 확약, 원인 창작, 정책 정면 위반). 수치 정확률과 독립적인 정보를 준다
7. **`EV-12` — RAG도 완벽하지 않다** — 함정 문항에서 `insufficient_info=true` 를 달아놓고 본문에서 *"기프트카드로 환급됩니다"* 를 단정했다. 평가셋 설계가 경고한 *"플래그는 맞고 본문은 창작"* 이 **RAG 조건에서도 발생**. 함정 회피가 플래그 기준 5/5, 본문 기준 4/5로 갈린다. **한계를 먼저 말하는 편이 방어에 강하다**
8. **`EV-37` — 베이스라인이 34%나 나온 이유** — 수리 기간 7~14일을 정책 없이 맞혔다. AI가 아무것도 못 맞춘 게 아니라 **일반 상식과 이 회사 정책이 우연히 겹칠 때만** 맞았다는 증거
9. **환각의 비용을 보여주는 두 건** — 베이스라인 `EV-42`는 정책상 복원 불가인 소멸 적립금을 *"전액 복구"* 확약, `EV-50`은 *"오늘 중 위약금 면제 완료"* + 가입 시 안내 누락이라는 **회사 귀책을 인정**했다. EV-17의 5,000원보다 실제 손해가 크다
10. **발송 후 수정 버그 (P-13)** — 사용자가 **엉뚱한 버튼을 눌러서** 발견됐다. 발송된 건의 옛 카드에서 `✏️` 가 먹혀 수정 루프가 돌았고, 그대로 승인하면 같은 고객에게 메일이 두 번 나갈 상황이었다. 승인 경로에는 방어가 있었는데 수정 경로에만 없었다. **정상 경로만 따라가는 검증으로는 절대 안 나오는 결함**이고, HITL 시스템에서 *"사람은 언제든 과거 UI를 다시 만진다"* 가 설계 전제여야 한다는 사례
11. **⚠️ 정책 충돌 실물** — `INQ-20260803-8384`. 담당자가 *"무료배송 기준이 3만원이라고 안내해줘"* 로 지시하자 모델이 **지시대로 본문을 쓰면서도** 그 문장을 집어내 DL-02 원문과 나란히 경고했다. 무대에서 그대로 재현 가능

## 접수 트리거 — 대안 2 (Apps Script → n8n Webhook)

Sheets 업데이트 트리거는 폴링이라 **최대 1분 지연**이 있다. 실행 수 문제는 없지만(빈 폴링은 차감되지 않음) 발표 데모에서 무대 정적이 생길 수 있다. 즉시성이 필요하면 아래로 교체한다.

**설치 위치:** 응답이 쌓이는 스프레드시트 → `확장 프로그램` → `Apps Script`
**트리거 설정:** 좌측 `트리거` → `트리거 추가` → 이벤트 유형 **`양식 제출 시`**

```javascript
function onFormSubmit(e) {
  const WEBHOOK_URL = 'https://<n8n-인스턴스>/webhook/replygate';  // n8n Webhook 노드 URL
  const v = e.namedValues;

  const payload = {
    received_at: new Date().toISOString(),
    customer_name:  v['이름']     ? v['이름'][0]     : '',
    customer_email: v['이메일']   ? v['이메일'][0]   : '',
    content:        v['문의내용'] ? v['문의내용'][0] : ''
  };

  UrlFetchApp.fetch(WEBHOOK_URL, {
    method: 'post',
    contentType: 'application/json',
    payload: JSON.stringify(payload),
    muteHttpExceptions: true
  });
}
```

> `v['이름']` 등의 키는 **구글 폼의 실제 질문 제목과 정확히 일치**해야 한다. 폼 질문을 바꾸면 스크립트도 같이 고칠 것.
> 둘 다 켜두면 같은 문의가 두 번 처리되므로, **웹훅으로 전환할 때는 Sheets 트리거를 반드시 비활성화**하거나 `inquiry_id` 기준 중복 방지 로직을 넣을 것.

## D1 검증 완료 (2026-08-01)

### ✅ Gemini — JSON 강제 출력 **가능**

무료 티어 + `gemini-3.6-flash` 에서 확인 완료. 아래 형식을 그대로 쓴다.

```json
{
  "contents": [{ "parts": [{ "text": "<프롬프트>" }] }],
  "generationConfig": {
    "responseMimeType": "application/json",
    "responseSchema": {
      "type": "object",
      "properties": {
        "category":  { "type": "string" },
        "sentiment": { "type": "string" },
        "summary":   { "type": "string" }
      },
      "required": ["category", "sentiment", "summary"]
    }
  }
}
```

- 엔드포인트: `POST https://generativelanguage.googleapis.com/v1beta/models/gemini-3.6-flash:generateContent?key=<KEY>`
- 스키마 `type` 은 **소문자·대문자 둘 다 동작.** 소문자로 통일한다.
- 코드펜스 없이 순수 JSON이 그대로 나온다. 그래도 파서에는 펜스 제거 + 1회 재시도 + 폴백(`기타`/`중립`)을 **보험으로 유지**한다.
- `response_format` 필드는 v1beta `generateContent` 에 **존재하지 않는다.** 쓰지 말 것.

### ✅ Gemini — 임베딩 **가능**

`gemini-embedding-001`, **3072차원**. `:embedContent` 로 호출. RAG 설계 그대로 진행.

문의 1건 = 생성 2회(P1+P2) + 임베딩 1회. **RPD 20이면 하루 10건이 상한**이라 데모도 평가셋도 불가능했다.

### ✅ 확정 모델 — `gemini-3.5-flash-lite`

| 용도 | 모델 |
|---|---|
| P1 분류·감정 / P2 초안 / P3 수정 | **`gemini-3.5-flash-lite`** |
| 임베딩 | **`gemini-embedding-001`** |

- 세 Gemini HTTP 노드 모두 **Retry On Fail (Max Tries 3, Wait 20000ms)** 을 건다. 429 대비.
- `gemini-flash-latest` 같은 **별칭은 쓰지 말 것.** 가리키는 대상이 바뀌면 발표 직전에 동작이 달라진다.

**왜 3.1 Flash Lite 가 아니라 3.5 인가 — 실측 근거 (`eval/모델비교_결과.md`)**

`compare_models.py` 로 정상 케이스와 함정 케이스(해외배송, 정책에 없음)를 3개 모델에 돌렸다.

- 정상 케이스: 셋 다 조항·수치 정확. 3.5 Lite 만 RF-13(7일)을 **조건문**으로 정확히 표현했고, 나머지 둘은 "이미 7일이 지났다"고 단정했다.
- 함정 케이스: **3.1 Flash Lite 가 환각을 냈다** — 정책에 없는 *"온마켓은 국내 배송만 지원한다"* 를 지어냈다. `insufficient_info` 플래그는 true 로 맞췄지만 본문에서 사실을 창작했다.
- 3.5 Flash Lite 는 *"정책에 명시되어 있지 않아 담당 부서 확인 후 안내"* 로 정확히 처리했다.
- 3.6 Flash 는 함정 케이스에서 **429** — RPD 20 소진. 제약이 실측으로 증명됐다.

> **모델을 역할별로 나누지 않는다.** 쿼터 분산을 노리고 P1/P2를 다른 모델에 태우려 했으나 3.1 Lite 의 환각 때문에 기각. RPD 500이면 문의 250건/일이라 하나로 충분하다.
> 이 비교 자체가 발표 소재다 — **제약 → 비교 실험 → 데이터 기반 선택**.

## n8n 워크플로우 임포트 시 반복되는 함정 (실측)

1. **Sheet 이름이 안 실린다.** JSON에 `sheetName` 을 넣어도 임포트 후 비어 있다. Sheets 노드를 전부 열어 `From list` 로 `문의` / `조항` 을 직접 지정해야 한다.
2. **Update Row 노드의 매핑이 초기화된다.** Sheet 를 지정해야 컬럼 목록이 로드되고, 그때 값이 빈 칸으로 나열된다. **빈 칸으로 두면 기존 값을 빈 값으로 덮어쓴다.** 🗑 아이콘으로 쓰지 않을 컬럼을 목록에서 제거할 것.
3. **Google Sheets Trigger 는 `row_number` 를 주지 않는다.** 그래서 첫 Update 는 **`타임스탬프` 컬럼으로 매칭**한다 (값은 `{{ $json.received_at }}`). 폼 제출 시각은 행마다 유일하다.
   - 이 첫 Update 에서 `inquiry_id` 를 시트에 써야 이후 모든 노드가 그것으로 행을 찾는다. 여기가 실패하면 전부 무너진다.
4. 값 칸의 `fx` 토글로 Expression / Fixed 를 전환한다. 고정 문자열(`분석중`, `0`)은 Fixed 로 둘 것.

**D1 검증 항목은 전부 통과했다.** 남은 미검증 항목 없음. 세부 결과는 `eval/D1_검증_체크리스트.md`.

### ✅ Gmail — Managed OAuth2 로 초안 생성·발송 모두 확인 (2026-08-01)

`Managed OAuth2 (recommended)` + `Sign in with Google` 만으로 끝. **Google Cloud OAuth 클라이언트 불필요.**
자격증명 화면에 `6 scopes available for Gmail credentials` 가 뜨고, 그 스코프로 `drafts.send` 까지 통과했다.

**⚠️ n8n Gmail 노드의 Draft 리소스에는 `Send` 오퍼레이션이 없다.** Create / Delete / Get / Get Many 뿐이다.
초안 발송은 **HTTP Request 노드로 Gmail API를 직접 호출**한다.

| 항목 | 값 |
|---|---|
| Method | `POST` |
| URL | `https://gmail.googleapis.com/gmail/v1/users/me/drafts/send` |
| Authentication | `Predefined Credential Type` |
| Credential Type | `Gmail OAuth2 API` |
| Body (JSON) | `{"id": "<draft_id>"}` |

- **Draft ID 는 Gmail 노드 출력의 최상위 `id`** (`r7233779028426606962` 형태). 안쪽 `message.id` 는 메시지 ID라 다른 값이다.
- 발송 성공 시 응답의 `labelIds` 가 `["UNREAD","SENT","INBOX"]` 로 온다.
- 수신자 지정 옵션의 UI 라벨은 `To Email` 이다 (내부 키는 `sendTo`).
- Draft 리소스에 `Update` 도 없다. **수정 루프에서는 기존 초안을 삭제하고 새로 생성**한다.

### 구글 자격증명 두 갈래

n8n Cloud 자격증명 화면 상단에 `Managed OAuth2 (recommended)` 드롭다운이 있으면 **n8n이 자기 구글 앱으로 대신 인증**해준다. 클라이언트 ID·시크릿·리디렉션 URI가 전부 불필요하고 Connect만 누르면 된다.
없거나 `Custom OAuth2` 만 있으면 Google Cloud에서 OAuth 클라이언트를 만들어야 한다 → `docs/셋업_가이드.md` B절.

> Google Cloud 콘솔이 새 UI(Google 인증 플랫폼)로 바뀌어 메뉴 이름이 다르다.
> 예전 "OAuth 동의 화면 → 범위" = 좌측 **데이터 액세스** / 테스트 사용자 추가 = 좌측 **대상**

## 수정 루프의 정책 충돌 감지 (2026-08-01 구현·검증)

수정 단계에서 **검토자가 정책을 잘못 기억해 지시하는 경우**를 잡는 장치. 초안 생성은 "정책에 없는 수치 금지"로 엄격한데 수정 단계만 무방비였던 문제를 메웠다.

**설계 원칙:** 지시를 무시하지 않는다. 본문은 검토자 지시대로 쓰고, **충돌을 카드에 표시해 사람이 판단**하게 한다. 승인 전이므로 아직 아무것도 발송되지 않았고 HITL 자체가 안전망이다.

P3 스키마에 필드 3개 추가:

| 필드 | 용도 |
|---|---|
| `handler_added` | 검토자 지시로 추가·변경된 내용 목록 |
| `policy_conflict.detected` | 충돌 여부 |
| `policy_conflict.instruction` | 문제가 되는 **본문 문장** |
| `policy_conflict.policy` | 충돌 조항 `[ID] 제목 — 원문` |

카드 표시:

```
🔴 [불량AS] 김태팔 — 수정 4회차
⚠️ 지시와 정책이 충돌합니다
   문제: 배송비는 고객이 부담해야 하며
   정책: [RF-05] 상품 하자 시 배송비 부담 — … 배송비는 전액 판매자가 부담합니다.
🔁 바뀐 점: …
✍️ 담당자 추가: …
📎 근거: AS-01, AS-04, RF-05
```

**핵심 설계 결정 3가지**

1. **대조 대상은 "이번 지시"가 아니라 "완성된 본문 전체"다.** 지시 단위로만 보면 수정이 누적될수록 초기 위반이 묻힌다. 실제로 3회차에서 경고가 사라졌다가 본문 기준으로 바꾸니 4회차에서도 계속 떴다.
2. **충돌 판정에는 전체 70조항을 넘기되 "충돌 확인 전용"이라고 못 박는다.** 검색된 3개만 보면 검색 밖 조항과의 충돌을 못 잡는다. 다만 용도를 제한하지 않으면 모델이 본문에 아무 조항이나 끌어와 검색 설계가 무의미해진다. 검증 결과 `📎 근거`는 흔들리지 않았다.
3. **수정 후에도 `cited_clauses` 를 유지한다.** 이전 규칙("어긋나는 조항 ID는 제외")이 근거를 통째로 비워 감사 추적이 끊겼다.

**남은 한계:** 충돌은 한 번에 하나만 표시된다(스키마가 객체 하나). 위반이 여러 개면 가장 심각한 것만 나온다.

**발표 포인트:** *"AI의 실수는 사람이 막고, 사람의 실수는 AI가 잡는다"* — 양방향 검증. 무대에서 일부러 정책과 다른 지시를 넣어 경고가 뜨는 장면을 보여줄 수 있다.

## 알아둘 사실 (이미 확인됨)

- **n8n 폴링 트리거는 새 데이터를 찾았을 때만 실행 1회로 계산된다.** 빈 폴링은 차감되지 않는다. (초기에 "하루 1440 실행" 이라고 잘못 판단했다가 정정)
- 정책 문서를 6종·150~200 조항으로 잡은 것은 의도적이다. 한 장짜리면 프롬프트에 통째로 넣는 게 정확해서 RAG를 쓸 명분이 없어진다.

### 스크립트 사용법

**프로젝트 루트에서 실행할 것.** 상대 경로로 `eval/` 에 저장한다.

```bash
$env:GEMINI_API_KEY="<키>"

python scripts/run_eval.py              # 전체 측정 (생성 150회, 약 12분)
python scripts/run_eval.py --limit 2    # 앞 2건만 시험 실행
python scripts/run_eval.py --reclassify # P1 분류만 재실행 (50회). 프롬프트 개정 시
python scripts/run_eval.py --score      # 검수표를 반영해 리포트만 재생성 (API 호출 0회)
```

**설계 원칙 두 가지**

- **중단돼도 이어서 실행된다.** 케이스마다 `eval/측정_원본.json` 에 저장한다
- **수치 검사는 리포트 단계에서 한다.** 지표를 고쳐도 API를 다시 부르지 않는다. 실제로 지표 오류를 발견해 `--score` 만으로 재계산한 적이 있다

> 측정 스크립트의 프롬프트는 **n8n 워크플로우와 동일해야 한다.** P1/P2/P4를 고치면 `scripts/run_eval.py` 와 워크플로우 양쪽을 함께 바꿀 것.

```powershell
# 실제 시트 연결 (서비스 계정 키 필요)
$env:REPLYGATE_SHEET_ID="<시트 ID>"; $env:REPLYGATE_SA_KEY="dashboard/keys/sa-key.json"; python dashboard/app.py
```

→ <http://127.0.0.1:8000>

- **서비스 계정 키는 `.gitignore` 로 막아뒀다** (`dashboard/*.json`, `dashboard/keys/`, `*service-account*.json`). 키를 두기 전에 `git check-ignore -v <경로>` 로 한 번 확인할 것
- 실험 결과 패널은 **데모 모드에서도 실제 측정값**을 읽는다 (`eval/측정_검수표.tsv`)
- 시트 조회가 실패해도 마지막 성공 값으로 화면이 유지된다. SSE가 끊기면 3초 폴링으로 자동 강등

## 배경 제약

- LLM API 예산 1~2만원 수준, 무료 한도 위주. GPU 없음 → 로컬 모델 서빙 배제
- 보유 자산: n8n Cloud, Gemini 무료 API 키, 텔레그램 봇 토큰, 디스코드 웹훅, 구글 워크스페이스, GitHub
- 구현 방식: 클로드 코드 바이브 코딩 + n8n GUI. **n8n 노드 설정은 GUI 기준으로 단계별 설명하고 붙여넣기용 JSON을 함께 주면 진행이 빠르다.**
