# ReplyGate

**AI가 쓰고, 사람이 승인해서 보내는 고객 응대 자동화**

Google Forms로 들어온 고객 문의를 Gemini가 사내 정책 문서(RAG)를 근거로 답변 초안을 작성하고,
담당자가 텔레그램 인라인 버튼으로 검토·수정·승인한 뒤에만 Gmail로 발송되는 **Human-in-the-Loop 고객 응대 시스템**.

## 왜 만들었나

LLM을 고객 접점에 그대로 붙이면 **환각이 그대로 고객에게 전달된다.** 환불 기한, 배송 지연 보상 범위처럼 **틀리면 분쟁이 되는 정보**를 AI가 단독으로 답하게 둘 수는 없다.

그렇다고 사람이 백지에서 다 쓰면 자동화의 의미가 없다. 그래서 실무는 이 구조를 쓴다.

```
AI 초안 생성  →  사람의 검토·승인  →  최종 발송
```

**핵심 주장: AI를 빠르게 만드는 것보다, AI를 통제 가능하게 만드는 것이 실무의 문제다.**

## 동작

```
[고객] Google Forms 문의
   │
   ▼  (Sheets 신규 행 감지)
[n8n 01] 분류·감정 판정 → 정책 조항 검색(RAG) → 답변 초안 생성 → Gmail 임시보관함 저장
   │
   ▼
[담당자] 텔레그램 카드 수신
   ├─ ✅ 발송 승인  →  Gmail 발송 → 완료 알림
   └─ ✏️ 수정 요청  →  자연어 지시 → AI 재작성 → 재검토 (승인까지 반복)
```

### 텔레그램 검토 카드

```
🔴 [교환반품] 김민석 — 반품 후 환불 지연 문의
📎 근거: RF-09, RF-02, RF-13
──────────────
안녕하세요 김민석 고객님, 온마켓 고객센터입니다.
반품 처리 과정에서 불편을 드려 진심으로 사과드립니다.
고객님의 반품건은 물류센터 도착일로부터 영업일 기준 2일 이내에
검수가 완료되며, 승인 후 영업일 기준 3일 이내에 환급됩니다. …

INQ-20260801-7602
[ ✅ 발송 승인 ]  [ ✏️ 수정 요청 ]
```

### 실제 화면 — 정책 충돌을 감지한 경우

<img src="docs/screenshots/텔레그램-정책충돌-감지.png" alt="담당자의 수정 지시가 정책과 충돌하자 경고를 띄운 텔레그램 카드" width="480" />

담당자가 *"무료배송 기준이 3만원이라고 안내해줘"* 라고 수정을 지시했는데, 정책 문서(`DL-02`)에는 무료배송 기준이 **5만원**으로 되어 있다.

이때 시스템은 지시를 그대로 따르지 않고 **`⚠️ 지시와 정책이 충돌합니다`** 를 띄워 양쪽 값을 나란히 보여준다. 담당자가 착각한 것인지 정책이 바뀐 것인지는 사람만 판단할 수 있으므로, **판단을 대신하지 않고 충돌 사실만 드러낸다.**

카드 하단에는 근거 조항(`DL-02`)과 수정 횟수가 함께 남고, 발송이 끝나면 옛 카드의 수정 버튼은 차단된다.

## 설계에서 신경 쓴 것

| | 내용 |
|---|---|
| **환각 차단** | 검색된 정책 조항 밖의 수치·조건은 쓰지 못하게 하고, 답할 수 없으면 `insufficient_info=true`로 "확인 후 안내"로 빠지게 했다 |
| **근거 추적** | 초안이 인용한 조항 ID를 카드에 함께 표시해 담당자가 3초 만에 검증할 수 있다 |
| **두 축 분류** | 감정(불만/일반)과 주문 조회 필요 여부(T/F)를 **직교하는 두 축**으로 판정한다. 앞은 초안 어조와 🔴/⚪ 배지를, 뒤는 📋 배지와 "주문번호 요청" 문구를 결정한다. 처음엔 3단계 하나로 묶었다가 측정에서 한 클래스가 전혀 쓰이지 않아 분리했다 |
| **양방향 검증** | AI의 실수는 사람이 막고, **사람의 실수는 AI가 잡는다.** 검토자 지시가 정책과 어긋나면 카드에 경고를 띄우되 지시 자체는 따른다 (판단은 사람 몫) |
| **동시 처리** | 검색 단계에서 아이템이 1:N으로 늘어나므로 Loop으로 문의를 한 건씩 격리 처리한다 |
| **순서 무관 승인** | 모든 조회를 `inquiry_id` 기준으로 해 여러 건을 뒤섞어 승인해도 어긋나지 않는다 |

## 실행 방법

`docs/셋업_가이드.md`를 따라 구글 폼·시트와 자격증명을 준비한 뒤:

1. `workflows/00_조항_임베딩_적재.json` 임포트 → **수동 1회 실행** (조항 70개 임베딩 적재, 약 5분)
2. `workflows/01_문의접수_초안생성.json` 임포트 → Publish
3. `workflows/02_승인_수정처리.json` 임포트 → Publish

임포트 후 아래 자리표시자를 본인 값으로 바꾸고, 각 노드의 자격증명을 드롭다운에서 지정해야 한다.

| 자리표시자 | 값 | 위치 |
|---|---|---|
| `GEMINI_API_KEY` | Gemini API 키 | 00에 1곳, 01에 3곳, 02에 1곳 |
| `SPREADSHEET_ID` | 구글 스프레드시트 ID | 00에 2곳, 01에 7곳, 02에 13곳 |
| `MANAGER_CHAT_ID` | 담당자 텔레그램 chat_id | 01에 1곳 |

n8n 임포트 시 반복되는 함정(Sheet 이름 누락, 매핑 초기화 등)은 `CLAUDE.md`에 정리해두었다.

### 대시보드

준비 없이 화면만 보려면:

```bash
REPLYGATE_DEMO=1 python dashboard/app.py
```

→ <http://127.0.0.1:8000> · 가짜 문의 12건으로 상황판이 채워진다. 실험 결과 패널은 데모 모드에서도 실제 측정값을 읽는다.

실제 시트에 연결하려면 구글 서비스 계정이 필요하다. 절차는 [`dashboard/README.md`](dashboard/README.md)에 있다. **시트에 고객 이메일이 들어 있어 "웹에 게시(CSV)" 대신 서비스 계정을 쓴다** — 시트를 비공개로 유지하기 위해서다.
