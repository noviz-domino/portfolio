## A. 빠른 시작 — JSON 붙여넣기

### A-1. 가져오기 절차

1. n8n Cloud → **Workflows** → **Create Workflow** (빈 캔버스)
2. `workflow/voc-agent-workflow.json` 파일을 텍스트 편집기로 열어 **전체 선택 → 복사**
3. n8n 캔버스를 클릭한 뒤 **Ctrl+V** — 노드 15개(`Loop Over Items` 루프 노드 포함, B장 참고)가 연결된 상태로 붙습니다
   - 또는 우측 상단 `⋯` → **Import from File** 로 JSON 파일을 직접 지정
4. 아래 A-2의 **교체 4곳**을 처리
5. 저장 → 테스트 → 마지막에 **Active 토글 ON**

> 이 JSON은 실제로 n8n Cloud에서 끝까지 빌드하고 여러 번 테스트하며 발견된 버그(트리거가 한 번에 여러 신규 행을 몰아서 감지하는 문제, 물품번호 앞자리 0 소실 문제 등)를 전부 반영한 **최종본**입니다. 발견 과정은 `03_개발일지.md`에 시간순으로 기록했습니다.

### A-2. 붙여넣은 뒤 반드시 교체할 4곳

캔버스 좌측 상단 노란 스티키 노트에도 같은 내용이 적혀 있습니다.

| # | 노드 | 무엇을 | 어떻게 |
| --- | --- | --- | --- |
| 1 | `Form 제출 감지`<br>`분석결과 시트 조회`<br>`분석결과 저장` | `YOUR_SPREADSHEET_ID` | 3개 노드 모두에서 Document → By ID 값을 본인 시트 ID로. Credential은 `Google Sheets OAuth2` 선택 |
| 2 | `Form 제출 감지` | Sheet 이름 `설문지 응답 시트1` | 실제 Form 응답 탭 이름과 다르면 드롭다운에서 다시 선택 |
| 3 | `Gemini 모델` | Credential | `Google Gemini(PaLM) API` 선택. Model은 `gemini-2.5-flash` 권장 (무료 쿼터 여유) |
| 4 | `Discord 알림` | `YOUR_DISCORD_WEBHOOK_URL` | URL 필드에 본인 Webhook URL 붙여넣기 |

> Credential은 JSON에 포함되지 않습니다(보안상 당연). 붙여넣은 직후 Google Sheets 노드 3개와 Gemini 모델 노드에 빨간 경고가 뜨는 게 정상이며, Credential을 지정하면 사라집니다.

### A-3. 붙여넣기가 실패하거나 노드가 빨갛게 깨질 때

n8n은 버전에 따라 노드 `typeVersion`이 다릅니다. JSON의 typeVersion이 설치 버전보다 높으면 노드가 깨집니다.

| 증상 | 조치 |
| --- | --- |
| `IF` 노드가 "Unknown node version" | JSON에서 `"typeVersion": 2.2` → `2` 로 낮춤 |
| `Gemini 분류`(chainLlm)가 안 붙음 | `"typeVersion": 1.5` → `1.4` 또는 `1` 로 낮춤 |
| `출력 스키마`가 안 붙음 | `1.2` → `1.1` 로 낮춤 |
| Google Sheets 노드가 안 붙음 | `4.5` → `4.4` 로 낮춤 |
| Gemini 계열 노드 자체가 목록에 없음 | H장의 **HTTP Request 대체안**으로 교체 |

## B. 노드 파이프라인 전체 구조

```
[1] Form 제출 감지            Google Sheets Trigger (rowAdded, 1분 폴링)
        │
[1-1] Loop Over Items         Split In Batches (batch size 1)  ← 한 번에 N건 감지돼도 1건씩 처리
        │ (loop 출력)
[2] 분석결과 시트 조회          Google Sheets - Get Rows  (alwaysOutputData: true)
        │                                 ↑ 중복판정 + 순번계산의 재료. 루프 반복마다 새로 조회한다
[3] 중복 체크                 Code (JS)   ← LLM 호출 이전!
        │
[4] IF 중복?
        ├── true ──> [5] 중복 종료 (NoOp) ─────────────┐  ← 저장·알림 없이 정상 종료
        └── false                                      │
             │                                          │
[6] Gemini 분류               chainLlm                   │
             ├── ai_languageModel ── [7] Gemini 모델 (lmChatGoogleGemini, temp 0)
             └── ai_outputParser ─── [8] 출력 스키마 (Structured Output Parser)
             │                                          │
[9] 검증 안전판               Code (JS)   ← 여기서 절대 throw 하지 않는다
             │                                          │
[10] 접수번호 생성             Code (JS)   ← 접수번호·접수시각·discord_message 생성
             │                                          │
[11] 분석결과 저장             Google Sheets - Append (Auto-map)
             │                            ↑ 검증 실패건도 예외 없이 저장
[12] IF 긴급? (urgency == 상)                            │
        ├── true ──> [13] Discord 알림 (HTTP POST) ──────┤
        └── false ─> [14] 긴급 아님 종료 (NoOp) ──────────┤
                                                          ▼
                                            [1-1] Loop Over Items 로 되돌아가 다음 건 처리
```

`중복 종료` / `Discord 알림` / `긴급 아님 종료` 3개 종료 지점은 전부 `[1-1] Loop Over Items`로 되돌아갑니다. 이게 없으면 트리거가 한 번에 여러 신규 행을 감지했을 때 첫 번째 건만 처리되고 나머지는 버려집니다 (`03_개발일지.md` "실제로 겪은 문제 6" 참고).

### 순서 제약 — 바꾸면 요구사항 위반

| 제약 | 근거 | 어기면 |
| --- | --- | --- |
| 중복 체크가 Gemini **앞** | REQ-03 "반드시 LLM 호출 이전에 차단" | 요구사항 위반 + 무료 쿼터 낭비 |
| 검증 안전판이 시트 저장 **앞** | REQ-05 | 허용값 밖 문자열이 시트에 들어가 통계 불가 |
| 시트 저장이 Discord 분기 **앞** | REQ-05 / REQ-06 | 긴급건만 기록되고 나머지 유실 |
| Loop Over Items가 트리거 **바로 뒤** | 한 번에 여러 신규 행 감지 시 개별 처리 | `.first()`가 항상 첫 건만 처리, 나머지 유실 |

## C. 노드별 설정 상세

### [1] Form 제출 감지 — `Google Sheets Trigger`

| 항목 | 값 |
| --- | --- |
| Poll Times | `Every Minute` |
| Document | By ID → 본인 스프레드시트 ID |
| Sheet | Form 응답 탭 (`설문지 응답 시트1`) |
| Trigger On | `Row Added` |

**출력 예시**
```json
{
  "타임스탬프": "2026. 8. 10 오후 2:32:10",
  "문의유형": "결제",
  "문의내용": "결제는 완료됐으나 주문 내역에 없고 고객센터 연결이 안 됩니다.",
  "이메일": "user@example.com",
  "물품 번호": "12345"
}
```

> ⚠️ **폴링 방식**이라 최대 1분 지연됩니다. 그리고 **워크플로우가 Active 상태여야** 폴링이 돕니다. 캔버스에서 `Test workflow`만 눌러본 상태로는 실제 폼 제출에 반응하지 않습니다 — 이걸 놓치면 "REQ-02를 구현했는데 안 돌아간다"로 한참 헤맵니다.

### [1-1] Loop Over Items — `Split In Batches`

| 항목 | 값 |
| --- | --- |
| Batch Size | `1` |
| 출력 | `done`(위, 미사용) / `loop`(아래, → 분석결과 시트 조회) |

**왜 필요한가**
처음엔 이 노드 없이 `Form 제출 감지` → `분석결과 시트 조회`로 바로 연결했습니다. 그런데 실제 테스트 중 1분 폴링 주기 안에 폼이 2건 제출되자 `Form 제출 감지`가 **2 items**를 한 번에 출력했고, 뒤에 있는 Code 노드들이 `.first()`로 짜여 있어서 **항상 첫 번째 건만 처리하고 두 번째 건은 조용히 사라졌습니다.** (`03_개발일지.md`에 이 문제를 발견하고 고친 과정이 자세히 있습니다.)

`Split In Batches`를 Batch Size 1로 넣으면 N건이 한꺼번에 감지되어도 한 건씩 순서대로 전체 파이프라인(중복확인→Gemini→검증→저장→알림)을 완주시키고, 끝나면 다시 이 노드로 돌아와 다음 건을 꺼냅니다. 덕분에:
- `분석결과 시트 조회`가 매 건마다 **그 시점 기준 최신 데이터**를 다시 읽으므로 같은 배치 안의 2건이 서로 중복인지도 정확히 잡습니다.
- 접수번호도 001, 002 순서로 정확히 이어집니다.

**코드에서 `.first()` 대신 `.item`을 쓰는 이유**
`중복 체크`, `검증 안전판` 노드의 `$('Form 제출 감지').item.json`이 핵심입니다. `.first()`는 트리거가 출력한 아이템 목록 중 무조건 0번째만 가리키므로 루프 안에서도 여전히 첫 건만 봅니다. `.item`은 n8n이 각 노드 실행 사이에 추적하는 "이 실행에 대응하는 원본 아이템(pairedItem)"을 따라가므로, 루프의 몇 번째 반복이든 **현재 처리 중인 그 건**을 정확히 가리킵니다.

### [2] 분석결과 시트 조회 — `Google Sheets (Get Rows)`

| 항목 | 값 |
| --- | --- |
| Resource / Operation | Sheet / `Get Row(s)` |
| Document | 본인 시트 ID |
| Sheet | `분석결과` |
| Filters | 없음 (전체 조회) |
| **Always Output Data** | **ON** ← 중요 |

**왜 Always Output Data가 필요한가**
분석결과 시트가 비어 있으면(헤더만 있으면) 이 노드는 **0개 아이템**을 출력합니다. n8n은 0개 아이템을 받은 노드를 **건너뜁니다**. 즉 첫 실행에서 중복 체크 이후 전부 스킵되어 아무 일도 일어나지 않습니다. `Always Output Data`를 켜면 빈 아이템 `{}` 하나를 내보내 뒤 노드들이 정상 실행됩니다. (코드에서 `Object.keys(r).length > 0` 필터로 빈 아이템을 걸러냅니다.)

### [3] 중복 체크 — `Code` (Run Once for All Items)

```javascript
const trigger = $('Form 제출 감지').item.json;

const norm = (v) => String(v ?? '').trim();
// 물품 번호는 숫자로 변환 후 다시 문자열화 → "00001" 과 1 을 같은 값으로 취급
// (Google Sheets가 셀 서식에 따라 앞자리 0을 지운 숫자로 읽어들이는 경우가 있어 실제로 중복이 안 잡힌 적이 있었다)
const normNo = (v) => String(Number(String(v ?? '').trim()) || v);

const itemNo = normNo(trigger['물품 번호']);
const email = norm(trigger['이메일']).toLowerCase();

const rows = $input.all()
  .map(i => i.json)
  .filter(r => r && Object.keys(r).length > 0);

const isDuplicate = rows.some(r =>
  normNo(r['물품 번호']) === itemNo &&
  norm(r['이메일']).toLowerCase() === email
);

return [{ json: { ...trigger, isDuplicate, _기존행수: rows.length } }];
```

**설계 근거**
- IF 노드가 아니라 Code 노드로 구현: IF는 "여러 행 중 하나라도 일치"를 표현하기 어렵습니다. `some()`이 훨씬 명확합니다.
- `_기존행수`는 디버깅용입니다. 중복이 안 잡힐 때 "시트를 아예 못 읽고 있는 건지(0)" vs "읽었지만 매칭 실패인지"를 즉시 구분할 수 있습니다.
- 이메일 `toLowerCase()`: `User@Example.com`과 `user@example.com`은 같은 사람입니다.
- `.item`(`.first()`가 아님): Loop Over Items 안에서 현재 반복에 대응하는 트리거 아이템을 정확히 가리키기 위함입니다 ([1-1] 참고).
- `normNo`: 물품 번호를 숫자로 한 번 변환했다가 다시 문자열화합니다. `"00001"`도 `1`도 전부 `"1"`이 되어, Google Sheets가 셀 서식 때문에 앞자리 0을 지우고 저장해도 같은 물품으로 인식합니다.

**검증 결과** (이 코드를 실제로 실행해 확인)

| 입력 | 시트 상태 | isDuplicate |
| --- | --- | --- |
| 물품 `"12345"`, `User@Example.com` | 빈 시트 | `false` ✅ |
| 물품 `"12345"`, `User@Example.com` | 시트에 숫자 `12345` + `user@example.com` | `true` ✅ |
| 물품 `"00001"` | 시트에 숫자 `1` (앞자리 0 소실) | `true` ✅ (normNo 적용 후) |

`normNo` 없이 단순 문자열 비교만 하면 `"00001" !== "1"`이 되어 중복을 놓칩니다. 실제로 이 문제 때문에 재실행 시 같은 문의가 계속 새로 쌓이는 버그를 겪었습니다 (`03_개발일지.md` 참고).

### [6] Gemini 분류 — `Basic LLM Chain (chainLlm)`

| 항목 | 값 |
| --- | --- |
| Prompt Source | `Define below` |
| Require Specific Output Format | **ON** (→ Output Parser 서브노드 활성) |

**프롬프트 전문**
```
당신은 종합 쇼핑몰의 고객 VOC(고객의 소리)를 분류하는 어시스턴트입니다.
아래 [문의내용]만 읽고 5개 필드를 판단하세요. 고객이 직접 고른 문의유형은 일부러 제공하지 않습니다. 내용만 근거로 판단하세요.
JSON 외의 설명, 서론, 코드블록 표기는 절대 출력하지 마세요.

[필드 정의]
- category : 결제 / 계정 / 상품 / 배송 / 기타 중 정확히 하나
- sentiment : 긍정 / 중립 / 부정 중 정확히 하나
- urgency : 상 / 중 / 하 중 정확히 하나
- summary : 한국어 요약. 80자를 절대 넘기지 마세요.
- needs_review : 분류에 확신이 없으면 true, 확실하면 false (문자열이 아닌 boolean)

[긴급도 판정 기준]
- 상 : 서비스를 못 쓰는 상태 / 금전적 피해가 이미 발생 / 법적 대응이나 언론·소비자원 제보 언급 / 명시적인 환불 요구
- 중 : 불편하지만 서비스 사용은 가능한 상태 / 단순 질문을 넘어선 개선 요청
- 하 : 단순 질문, 칭찬, 정보 확인

[문의내용]
{{ $json['문의내용'] }}
```

**프롬프트 설계 원칙 5가지**

1. **긴급도 기준을 프롬프트에 그대로 명시** — REQ-04의 명시적 요구사항입니다.
2. **허용값을 열거형으로 못박음** — "적절히 분류하세요" 같은 열린 지시는 `결제/환불` 같은 창작을 유발합니다.
3. **고객이 고른 `문의유형`은 프롬프트에 넣지 않음** — 넣으면 LLM이 그대로 따라가서(anchoring) "고객 선택 vs LLM 분류" 비교의 독립성이 사라집니다. REQ-01이 이 값을 "비교하는 재료"라고 규정했으므로 두 판단은 분리되어야 합니다.
4. **summary 80자를 프롬프트에 쓰고 코드에서도 `slice`로 강제** — 프롬프트는 부탁이고, 코드가 계약입니다.
5. **`needs_review`가 boolean임을 명시** — LLM이 문자열 `"true"`를 보내는 대표적 실패를 프롬프트 레벨에서 1차 예방합니다.

### [7] Gemini 모델 — `Google Gemini Chat Model`

| 항목 | 값 |
| --- | --- |
| Credential | Google Gemini(PaLM) API — 보유 중인 키 |
| Model | `models/gemini-2.5-flash` |
| Temperature | **0** |

Temperature 0의 이유: 이 프로젝트의 목적 중 하나가 "사람마다 달라서 통계를 낼 수 없던 분류 기준의 통일"입니다. 같은 문의가 실행할 때마다 다르게 분류되면 문제를 그대로 재현하는 셈입니다.

### [8] 출력 스키마 — `Structured Output Parser`

Schema Type = `Manual` 로 두고 아래 JSON Schema를 입력합니다.

```json
{
  "type": "object",
  "properties": {
    "category":     { "type": "string", "enum": ["결제", "계정", "상품", "배송", "기타"] },
    "sentiment":    { "type": "string", "enum": ["긍정", "중립", "부정"] },
    "urgency":      { "type": "string", "enum": ["상", "중", "하"] },
    "summary":      { "type": "string" },
    "needs_review": { "type": "boolean" }
  },
  "required": ["category", "sentiment", "urgency", "summary", "needs_review"]
}
```

> Parser가 있어도 REQ-05의 검증 안전판은 **반드시** 따로 필요합니다. Parser는 파싱에 실패하면 **에러를 던져 워크플로우를 중단**시킵니다. 요구사항은 "출력이 계약을 어겨도 워크플로우가 죽으면 안 된다"이므로, 코드로 방어하는 노드가 별도로 있어야 합니다. Parser는 1차 방어, 안전판은 최종 방어입니다.

### [9] 검증 안전판 — `Code`

```javascript
const trigger = $('Form 제출 감지').item.json;
const raw = $input.first().json;

const ALLOWED = {
  category: ['결제', '계정', '상품', '배송', '기타'],
  sentiment: ['긍정', '중립', '부정'],
  urgency: ['상', '중', '하'],
};

// ── 함정3 방어 : Gemini 가 ```json ... ``` 코드펜스나 설명문을 섞어 보내도 JSON 을 건져낸다.
// 어떤 경우에도 throw 하지 않는다 (REQ-05 : 워크플로우가 죽으면 안 됨)
function extractJson(input) {
  if (input && typeof input === 'object') {
    if (input.output && typeof input.output === 'object') return input.output;
    if (typeof input.output === 'string') return extractJson(input.output);
    if (typeof input.text === 'string') return extractJson(input.text);
    return input;
  }
  let s = String(input ?? '').trim();
  s = s.replace(/^```(?:json)?/i, '').replace(/```$/, '').trim();
  const start = s.indexOf('{');
  const end = s.lastIndexOf('}');
  if (start !== -1 && end > start) s = s.slice(start, end + 1);
  try { return JSON.parse(s); } catch (e) { return null; }
}

const llm = extractJson(raw);
const g = (k) => (llm && llm[k] !== undefined && llm[k] !== null) ? llm[k] : undefined;

let violated = false;
const 위반사유 = [];

if (llm === null) {
  violated = true;
  위반사유.push('JSON 파싱 실패');
}

// 1) 필수 필드 누락 검사
for (const k of ['category', 'sentiment', 'urgency', 'summary', 'needs_review']) {
  if (g(k) === undefined) { violated = true; 위반사유.push(`${k} 누락`); }
}

// 2) 허용값 위반 검사
for (const k of ['category', 'sentiment', 'urgency']) {
  if (g(k) !== undefined && !ALLOWED[k].includes(g(k))) {
    violated = true;
    위반사유.push(`${k} 허용값 위반(${g(k)})`);
  }
}

// 3) 타입 / 길이 검사
if (g('summary') !== undefined && typeof g('summary') !== 'string') { violated = true; 위반사유.push('summary 타입 불일치'); }
if (typeof g('summary') === 'string' && g('summary').length > 80) { violated = true; 위반사유.push('summary 80자 초과'); }
// 함정4 방어 : LLM 이 문자열 "true" 를 보내는 경우도 계약 위반으로 잡는다
if (g('needs_review') !== undefined && typeof g('needs_review') !== 'boolean') { violated = true; 위반사유.push('needs_review 타입 불일치'); }

// ── 안전한 기본값으로 교정 (중단하지 않고 통과시킨다)
const safe = {
  category: ALLOWED.category.includes(g('category')) ? g('category') : '기타',
  sentiment: ALLOWED.sentiment.includes(g('sentiment')) ? g('sentiment') : '중립',
  urgency: ALLOWED.urgency.includes(g('urgency')) ? g('urgency') : '중',
  summary: typeof g('summary') === 'string' ? g('summary').slice(0, 80) : '',
  needs_review: g('needs_review') === true,
};

// REQ-05 : 검증 실패 시 urgency 는 안전한 기본값 '중', needs_review 는 true
if (violated) {
  safe.urgency = '중';
  safe.needs_review = true;
}

return [{ json: { ...trigger, ...safe, _위반사유: 위반사유.join(', ') } }];
```

**3중 방어 구조**

| 층 | 무엇을 막는가 |
| --- | --- |
| `extractJson`의 객체 분기 | Parser 사용 시 `{output: {...}}`, 미사용 시 `{text: "..."}`, 날값 객체 — 3가지 형태 모두 흡수 |
| 코드펜스 제거 + `{`~`}` 구간 추출 | 함정3. 코드블록 래핑, "네, 분석했습니다:" 같은 서론 |
| `try/catch` → `null` | 완전히 JSON이 아닌 응답. throw 대신 null을 반환해 워크플로우 생존 |

**검증 결과** (이 코드를 실제로 실행해 확인)

| 입력 | category | urgency | needs_review | _위반사유 |
| --- | --- | --- | --- | --- |
| 정상 JSON (urgency=상) | 결제 | **상** | false | (없음) |
| 코드펜스 + `category:"결제결제"` + `urgency:"매우높음"` + `needs_review:"true"` | 기타 | **중** | **true** | category 허용값 위반, urgency 허용값 위반, needs_review 타입 불일치 |
| `"죄송합니다 분류할 수 없습니다"` | 기타 | **중** | **true** | JSON 파싱 실패, 5필드 전부 누락 |

세 경우 모두 **예외를 던지지 않고** 통과했습니다 = REQ-05 충족.

**`_위반사유` 열을 시트에 추가할지**
현재는 시트에 저장하지 않고 실행 로그에서만 볼 수 있습니다. 디버깅이 훨씬 편해지므로, 원한다면 `분석결과` 시트에 `_위반사유` 열을 12번째로 추가하면 자동으로 기록됩니다(Auto-map이 키 이름으로 매칭하므로 코드 수정 불필요). 요청서에 없는 열이므로 기본은 미포함으로 두었습니다.

> ⚠️ **알아두어야 할 트레이드오프**
> 요구사항 그대로 "위반 시 urgency=중"을 구현했습니다. 그래서 LLM이 urgency를 `상`으로 정확히 판단했는데 summary만 81자였다면, **긴급건이 중으로 강등되어 Discord 알림이 안 갑니다.** 요청서 REQ-05가 명시한 동작이라 그대로 따랐지만, 실제 운영이라면 "심각도와 무관한 위반(summary 길이 등)은 urgency를 건드리지 않고 needs_review만 true"로 분리하는 편이 안전합니다. 그렇게 바꾸려면 `if (violated)` 블록을 아래처럼 나눕니다.
> ```javascript
> const 치명적위반 = 위반사유.some(r => r.includes('urgency') || r.includes('파싱 실패'));
> if (치명적위반) safe.urgency = '중';
> if (violated) safe.needs_review = true;
> ```

### [10] 접수번호 생성 — `Code`

```javascript
const item = $input.first().json;

// ── 함정2 방어 : '2026/08/10 오후 2:32:10' 같은 한국어 타임스탬프는 new Date() 로 파싱되지 않는다.
// 문자열에서 숫자를 순서대로 뽑아 직접 조립하고, 오전/오후를 반영한다.
function parseTimestamp(rawValue) {
  const s = String(rawValue ?? '').trim();
  if (!s) return null;
  const nums = s.match(/\d+/g);
  if (!nums || nums.length < 5) return null;
  let [y, mo, d, h, mi] = nums.slice(0, 5).map(Number);
  const sec = nums.length >= 6 ? Number(nums[5]) : 0;
  if (/오후|PM/i.test(s) && h < 12) h += 12;
  if (/오전|AM/i.test(s) && h === 12) h = 0;
  if (y < 1000 || mo < 1 || mo > 12 || d < 1 || d > 31 || h > 23 || mi > 59) return null;
  const dt = new Date(y, mo - 1, d, h, mi, sec);
  return isNaN(dt.getTime()) ? null : dt;
}

const base = parseTimestamp(item['타임스탬프']) ?? new Date();
const p2 = (n) => String(n).padStart(2, '0');
const dateStr = `${base.getFullYear()}${p2(base.getMonth() + 1)}${p2(base.getDate())}`;
const 접수시각 = `${base.getFullYear()}-${p2(base.getMonth() + 1)}-${p2(base.getDate())} ${p2(base.getHours())}:${p2(base.getMinutes())}`;

// 같은 날짜의 '최대 순번 + 1' (단순 개수 세기가 아니라 최댓값 → 중간 행을 지워도 번호가 겹치지 않는다)
const rows = $('분석결과 시트 조회').all()
  .map(i => i.json)
  .filter(r => r && Object.keys(r).length > 0);

const prefix = `VOC-${dateStr}-`;
let maxSeq = 0;
for (const r of rows) {
  const no = String(r['접수번호'] ?? '');
  if (no.startsWith(prefix)) {
    const n = parseInt(no.slice(prefix.length), 10);
    if (!isNaN(n) && n > maxSeq) maxSeq = n;
  }
}
const 접수번호 = `${prefix}${String(maxSeq + 1).padStart(3, '0')}`;

// REQ-07 : 원문은 200자까지, 초과 시 말줄임
const body = String(item['문의내용'] ?? '');
const 원문 = body.length > 200 ? body.slice(0, 200) + '...' : body;

const discord_message = [
  '🚨 긴급 VOC 접수',
  `접수번호 : ${접수번호}`,
  `분류     : ${item.category} / ${item.sentiment}`,
  `요약     : ${item.summary}`,
  `원문     : ${원문}`,
  `접수시각 : ${접수시각}`,
].join('\n');

// 시트 헤더와 '정확히 같은 키' 로 내보낸다 → Append 노드의 Auto-map 이 그대로 매핑한다
return [{
  json: {
    '접수번호': 접수번호,
    '접수시각': 접수시각,
    '문의유형(고객선택)': item['문의유형'] ?? '',
    '문의내용': body,
    '이메일': item['이메일'] ?? '',
    '물품 번호': String(item['물품 번호'] ?? ''),
    'category': item.category,
    'sentiment': item.sentiment,
    'urgency': item.urgency,
    'summary': item.summary,
    'needs_review': item.needs_review,
    discord_message,
  }
}];
```

**설계 근거 4가지**

1. **숫자 추출 방식 파싱** — Google Sheets 타임스탬프 포맷은 계정 지역설정에 따라 `2026. 8. 10 오후 2:32:10` / `2026/08/10 오후 2:32:10` / `2026-08-10 14:32:10` 로 달라집니다. 포맷별 정규식을 나열하는 대신 "숫자를 순서대로 6개 뽑고 오전/오후만 반영"하면 세 포맷 모두 커버됩니다.
2. **개수 세기(count)가 아니라 최댓값(max)+1** — count 방식은 시트 중간 행을 하나 지우면 이미 존재하는 번호를 재발급합니다. max 방식은 안전합니다.
3. **discord_message를 여기서 완성** — HTTP Request 노드의 body에 긴 표현식을 쓰면 편집·디버깅이 어렵습니다. Code 노드에서 문자열까지 만들어두면 HTTP 노드는 한 줄로 끝납니다.
4. **시트 헤더와 동일한 키로 출력** — Append 노드를 `Auto-map`으로 쓸 수 있어, 11개 열을 하나하나 수동 매핑하는 작업과 그 과정의 오타 위험이 사라집니다. `discord_message`처럼 헤더에 없는 키는 Auto-map이 그냥 무시합니다.

**검증 결과** (이 코드를 실제로 실행해 확인)

시트에 `VOC-20260810-001`, `VOC-20260810-003`, `VOC-20260809-009`가 있고 타임스탬프가 `2026. 8. 10 오후 2:32:10`일 때:
- 접수번호 → `VOC-20260810-004` ✅ (같은 날짜 최댓값 003 + 1, 다른 날짜 009는 무시)
- 접수시각 → `2026-08-10 14:32` ✅ (오후 2시 → 14시 변환)

타임스탬프 포맷 변형:

| 입력 | 결과 접수시각 |
| --- | --- |
| `2026/08/10 오후 2:32:10` | `2026-08-10 14:32` ✅ |
| `2026-08-10 14:32:10` | `2026-08-10 14:32` ✅ |
| `2026. 8. 10 오전 12:05:00` | `2026-08-10 00:05` ✅ (오전 12시 → 0시) |
| `깨진값` | 실행 시각으로 폴백 ✅ (죽지 않음) |

원문 250자 입력 시 → `원문     : ` 뒤 200자 + `...` ✅

### [12] IF 긴급? — `IF`

| 항목 | 값 |
| --- | --- |
| 조건 | `{{ $('접수번호 생성').first().json.urgency }}` → String → **is equal to** → `상` |

**왜 `$json.urgency`가 아니라 노드를 직접 참조하나**
바로 앞이 Google Sheets Append 노드입니다. Append 노드의 출력은 "시트에 쓴 결과"이며 버전·설정에 따라 원본 필드를 온전히 넘기지 않을 수 있습니다. `접수번호 생성` 노드를 명시적으로 참조하면 앞 노드의 출력 형태와 무관하게 항상 정확한 값을 읽습니다.

## D. 함정 정리 — 어디서 어떻게 막았는가

| # | 함정 | 방어 위치 | 방어 방법 |
| --- | --- | --- | --- |
| 1 | Sheets Trigger가 폴링이고 Active 필수 | 운영 절차 | Poll = Every Minute, 완성 후 Active ON 필수 체크 |
| 2 | 한국어 타임스탬프 `new Date()` 파싱 실패 | [10] | 숫자 추출 파싱 + 오전/오후 처리 + 실패 시 실행시각 폴백 |
| 3 | Gemini가 JSON을 코드펜스로 래핑 | [8] + [9] | Output Parser 1차, `extractJson` 코드펜스 제거·`{}` 구간 추출 2차 |
| 4 | `needs_review`가 문자열 `"true"` | [9] | `typeof !== 'boolean'` 검사 → 계약 위반 처리 |
| 5 | 중복 체크 타입 불일치 (숫자 vs 문자열) | [3] | 양쪽 `String().trim()`, 이메일 `toLowerCase()` |
| 6 | 빈 시트에서 Get Rows가 0 아이템 → 이후 스킵 | [2] | `Always Output Data` ON + 코드에서 빈 아이템 필터 |

## H. 대체안 — Gemini 노드가 없거나 Structured Output이 안 될 때

`chainLlm` + `lmChatGoogleGemini` 조합 대신 **HTTP Request 노드 하나로** Gemini REST API를 직접 호출할 수 있습니다. `responseSchema`를 API에 직접 주므로 구조화 출력이 더 확실합니다.

`Gemini 분류` / `Gemini 모델` / `출력 스키마` 3개 노드를 지우고, 아래 HTTP Request 노드 하나를 `IF 중복?`의 false 분기 → `검증 안전판` 사이에 넣습니다.

| 항목 | 값 |
| --- | --- |
| Method | `POST` |
| URL | `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent` |
| Authentication | Generic → Header Auth (Name `x-goog-api-key`, Value = API 키) |
| Send Body | ON, JSON |

**JSON Body**
```
={{ JSON.stringify({
  contents: [{ parts: [{ text: "당신은 종합 쇼핑몰의 고객 VOC를 분류하는 어시스턴트입니다.\n[문의내용]만 근거로 판단하세요.\n\n[긴급도 판정 기준]\n- 상 : 서비스를 못 쓰는 상태 / 금전적 피해 발생 / 법적 대응·언론·소비자원 제보 언급 / 명시적 환불 요구\n- 중 : 불편하지만 사용은 가능 / 개선 요청\n- 하 : 단순 질문, 칭찬, 정보 확인\n\nsummary 는 80자 이하로 작성하세요.\n\n[문의내용]\n" + $json['문의내용'] }] }],
  generationConfig: {
    temperature: 0,
    responseMimeType: "application/json",
    responseSchema: {
      type: "OBJECT",
      properties: {
        category:     { type: "STRING", enum: ["결제","계정","상품","배송","기타"] },
        sentiment:    { type: "STRING", enum: ["긍정","중립","부정"] },
        urgency:      { type: "STRING", enum: ["상","중","하"] },
        summary:      { type: "STRING" },
        needs_review: { type: "BOOLEAN" }
      },
      required: ["category","sentiment","urgency","summary","needs_review"]
    }
  }
}) }}
```

이 경우 응답은 `candidates[0].content.parts[0].text`에 JSON 문자열로 들어옵니다. `검증 안전판` 코드의 `extractJson` 함수 맨 앞에 아래 한 줄만 추가하면 나머지는 그대로 동작합니다.

```javascript
// HTTP Request 대체안 사용 시 응답 껍데기 벗기기
if (input?.candidates?.[0]?.content?.parts?.[0]?.text) {
  return extractJson(input.candidates[0].content.parts[0].text);
}
```

> 이 대체안은 Credential 설정이 조금 더 번거롭지만, n8n 버전 차이에 영향받지 않고 `responseSchema`로 허용값까지 API 레벨에서 강제된다는 장점이 있습니다. 기본안이 잘 붙으면 그대로 쓰고, 막히면 이걸로 갈아타세요.
